## Запуск

Из `repo/`: `node tools/showcase_record.js <id>`. Сборка — из `dist`; если `src/` правит другая
сессия, писать со снимка: скопировать `dist/main.js` и `dist/styles.css` в scratchpad и
`IO_MAIN=<снимок main.js> IO_STYLES=<снимок styles.css>`. Финальные GIF к выпуску — на сборке
выпуска. `IO_DRY=1` — шаги без кадров, `IO_TRACE=1` — печать каждого шага.

Шаги (полный список и точный смысл — шапка `tools/showcase_record.js`):

```
title <заголовок> | <строка>  заставка в начале GIF — обязательна в каждом
open <файл>                 заметка (до первого кадра)
caret <строка>[ @ <кусок>]  каретка в конец строки с ровно этим текстом или перед куском
select <строка> @ <кусок>   кусок выделен
say <фраза>                 субтитр
cmd <id команды>            команда плагина: клавишу назначает инструмент, плашка — имя из палитры;
                            подсветка идёт за правкой, а без правки — за кареткой (прыжки)
key <Ctrl+A | Enter …>      когда фича сама и есть клавиша; плашка — клавиша
type <текст>                набор текста
stage <подпись>             новый этап полосы, назван сценарием; есть хоть один — `settings` этапа не начинает
drop <Field>                Field (и дочерний) убран за кадром — в панели только нужное GIF
room <px>                   запас высоты окна под заметкой
spot <текст>[ #N]           рамка вокруг узла панели, о котором субтитр (строка списка Fields; заголовок раздела — с разделом);
                            снимается щелчком `click` — окно, открытое щелчком, рамка не обводит
tip <строка>                раскрыть «?» строки панели (`::after` имени; `set … = ?` щёлкал переключатель)
line-width <px>              колонка текста уже: место под плашку слева от коротких строк
mark none | line | prefix | caret   акцент нажатия: none (умолчание) — ничего, line — строка (перенос, склейка),
                            prefix — отступ и Prefix, caret — светится каретка (прыжки)
rec-caret off               родная каретка вместо фиолетовой (GIF про саму каретку)
settings <вкладка>          вход в настройки = новый этап; заметки — к исходным под панелью
set <контрол>[ #N] = <значение>  N-й с тем же именем; список, on/off, кнопки-варианты, текст, ползунок (число), цвет (#rrggbb); потом панель закрывается сама; строки редактора Fields тоже (`set Child Field = Always`)
fill <подсказка> = <текст>  поле без имени строки (свой блок панели), по placeholder; без него — по aria-label (`Custom text for #todo`)
pick <подпись> = <вариант>  список без имени строки (свой блок панели); ячейка Show — `pick Show, for #todo = custom`
hover <текст>[ #N][ + Ctrl] указатель на узел (и куда смотрит панель при открытии); с Ctrl — превью ссылки
click <текст>[ #N] / close  для показов в самой панели; #N — N-е совпадение сверху; после set панель
                            остаётся открытой, если следующий шаг в панели (click, fill, pick, pause, close); значок без текста — по aria-label (`click Make #review a child Value`)
expect <строка / строка>    порядок строк заметки; не сошлось — запись падает
expect ?                    напечатать заметку (черновик ожидания)
```

Id команд — `window.app.commands.commands` с приставкой `inline-overhaul:` (без неё в шаге).
Параллельные записи — каждая со своим `IO_PORT`. Инструмент правит одна сессия: нужен новый шаг —
его просят у главной сессии, а не дописывают рядом.

## Порядок на одну фичу

1. **Разбор** — группа в `docs/SETTINGS.md`, ключевые контролы, что каждое значение меняет в заметке.
2. **Демо-заметка** — минимальная, где каждое значение видно одним-двумя нажатиями.
3. **Черновик шагов с `expect ?`** после каждого показа, прогон `IO_DRY=1` — поведение
   смотреть **на стенде, а не по памяти** (2026-09-25 так нашлось, что `Whole tree` забирает
   чужие подпункты). Находка, которая на GIF выглядит поломкой, — вопрос в OPEN_QUESTIONS,
   а не подбор удобной заметки.
4. **Ожидания** выписать с напечатанного; первая часть `expect` — строка без отступа
   (начало аргумента обрезается).
5. **Запись**, затем проверка кадров (раздел «Проверка»), затем таблица в `<id>.md` и
   строка каталога.
6. После его общей приёмки — запись в `docs/SHOWCASE.md`, старый GIF удалить,
   `tests/regression/docs_terms_tests.ts` зелёный.

## Каркас сценария (его ответы 2026-10-05 после приёмки образцов)

Порядок этапов любого GIF — сверху вниз, лишнее пропускается:

1. `title` — заставка: что покажет GIF.
2. **`Default Obsidian`** — первым этапом везде, где у Obsidian своё поведение на ту же клавишу или
   действие (Move lines, Jump inside a line/note, Ctrl+A, Smart Enter, Smart paste, Smart Delete,
   глобальные клавиши). Отдельного GIF «до» нет: `move-lines-before` становится первым этапом `move-lines`.
3. **Включение функции на камеру** — везде, где у неё есть главный переключатель (`Move cursor inside a
   line`, `Smart Enter`, `Smart paste`, `Expanded Ctrl+A`, `Tag Bars`…): переключатель выключен `preset`
   до ролика, этап — `settings` + `set <переключатель> = on` + первый показ. Нет переключателя (Fields,
   tagWheel) — сразу показ.
4. **Один контрол — один этап**, по порядку панели. Остальные контролы этапа выставлены `preset`
   заранее: на камеру включается только то, что этап показывает.
5. **Рамка `spot` — где показывается устройство панели** (Fields, Values, Blocks, Binder, таблица
   хоткеев, Backup): рамка на предмет и субтитр «это …». На простом переключателе рамки нет — туда
   идёт указатель.

Этап — одна мысль. Подпись этапа на полосе и первый субтитр этапа говорят одно и то же
(`Step size → Sentence`); этап загорается вместе со своим субтитром.

## Правила кадра — каждое его замечание по образцу

**Окно**
- **Высота — по заметке** (его слово 2026-10-05: «многие gif выглядят пустыми»): окно ужимается
  до последней строки + место под субтитр; в GIF с панелью настроек — не ниже 560 px, чтобы
  панель читалась. Ширина — как при первом запуске Obsidian. Скрыты боковые панели, лента,
  строка состояния. Интерфейс английский, тема светлая стандартная, кегль 20. Всё это делает
  инструмент.
- Первый кадр — чистая заметка: ни окна доверия, ни уведомлений (инструмент падает, если есть).

**Этапы и полоса прогресса (его слова 2026-10-04 и 2026-10-05)**
- Полоса — **под кадром**, своей заливкой (текст на неё не залезает), собирается при
  кодировании: блоки этапов шириной по доле времени, текущий залит, прошедшие светлее, под
  ними фиолетовая полоска просмотра **как в видео** — растёт от начала GIF до конца (его слово
  2026-10-05 ко всем трём образцам: прежняя через `drawbox` стояла на месте; теперь `overlay`,
  у него `x` считается на каждом кадре).
- **Этапы называет сценарий шагом `stage`.** `Default Obsidian` — только этап, где показано
  поведение Obsidian без плагина (прыжки, Delete, глобальные клавиши); остальные — по
  сценарию (`Status Field and its Values`, `Smart Delete`). Этап начинается не обязательно
  заходом в настройки (в `fields` этапы 2 и 3 — tagWheel). Без шагов `stage` — прежние
  подписи (последний субтитр перед `settings`).
- **Отката заметки на экране нет никогда.** Заметка возвращается к исходной под панелью
  настроек; после выхода — свежая заметка. Внутри этапа заметка правится подряд.
- Следствие для сценария: показы внутри этапа не должны отменять друг друга (перенос
  заголовка, возвращающий строку на место, зритель видит как Ctrl+Z). Порядок показов
  этапа подбирать на стенде.

**Настройки**
- Камера на панели плагина: окно настроек на весь экран, без левого списка Obsidian, крупно.
- Полный путь к плагину не показывается: панель за кадром выбрана на inlineOverhaul и нужной
  вкладке, `Ctrl+,` открывает сразу там. Плашки `Ctrl+,` нет — к фиче не относится.
- **Панель открывается сразу на нужном месте** (его слово 2026-10-05): невидимой
  прокручивается к контролу первого шага в ней (`set`/`click`/`fill`/`pick`/`hover`) и
  только потом показывается. Контрол уже в кадре — прокрутки нет.
- Указатель идёт к контролу, щелчок — затухающий круг. Крестика нет: панель закрывается
  сама после контрола. Закрылась панель или нажата клавиша — указатель прячется.
  Время в панели — минимум, GIF про поведение в заметке.
- **В панели — только то, что нужно GIF** (`drop` лишних Field за кадром).
- **В панели показ объясняется рамкой** (его слово 2026-10-05 к fields: «я не понял, на что смотреть»): `spot` на предмет и `say`, что это (`This is a Field — it contains Values`). Первая рамка этапа ставит панель у верха — следующий раздел виден без прокрутки.
- **Контролы, не относящиеся к этапу, выставлены заранее** `preset` (его слово к smart-delete): на камеру — только включение того, что показывает этап.
- **Этап плагина начинается с включения его контрола на камеру** (его слово к jump-line): сам контрол выключен `preset` до ролика, первый этап после `Default Obsidian` — `settings` и `set <контрол> = on`.

**Заставка (его слово 2026-10-04 к move-lines-before: «я не понял, что тут происходит»)**
- Первые ~3 с — заставка: заголовок фичи и одна строка, что она даёт. Шаг `title`, в каждом GIF.

**Каретка (его слова 2026-10-04 и 2026-10-05)**
- Каретка записи — фиолетовая, 4 px, мигает чаще родной; родная спрятана.
  `rec-caret off` — только в `cursor`.
- **Гало у каретки нет** (его слово к jump-line): в `mark caret` она просто не мигает во время
  нажатий. В открытом tagWheel каретки нет вовсе: смотреть на панель.
- **Акцент выбирает сценарий**: строка (`mark line`), Prefix и отступ (`mark prefix`),
  каретка (`mark caret`) или ничего, если и так видно, куда смотреть.

**Нажатие в заметке**
- **Фон строки — только там, где фича двигает строки** (`mark line`: move-lines, «до»). В
  остальных GIF он «сбивает» и сливается с подсветкой самого плагина (его замечания к пяти
  GIF 2026-10-04): умолчание `mark none`, смотреть на каретку. Где суть — Prefix и отступ,
  подсвечиваются они (`mark prefix`). Подсветка — только фон, без полос и рамок.
- Нажатие — вспышка фиолетового на плашке (его слово 2026-10-04: «чтобы было более явно»).
- **Плашка — там, куда смотреть** (его слова к трём образцам): над кареткой и идёт за ней;
  задевает текст другой строки — слева от начала строки; в открытом tagWheel — всегда слева от
  строки и окна Scroller (смотрят на ячейку в начале строки); в `mark caret` (прыжки) — всегда над
  кареткой. Слева тесно — справа от конца строки. Мало места слева у коротких строк —
  `line-width <px>` сужает колонку текста (в `fields` — 480).
- **Плашка вспыхивает в момент нажатия и затухает** через ~1,3 с; следующее нажатие сменяет её,
  а не ложится рядом. Текст — **имя команды из палитры**: `hotkey: Move up`, а не сочетание клавиш.
- Подсветка (`mark line`) едет вместе со строкой в том же кадре и растягивается на то, что поехало с ней
  (поддерево, раздел). Её ведёт сама страница каждый кадр — запаздывающая подсветка «очень
  плохо», пользователь теряет фокус.
- Показ «ничего не происходит» (граница держит, ограничение) — несколькими нажатиями с
  места, откуда видно движение до границы и остановку на ней: плашка мигает, строка стоит.

**Заметка**
- Структура, за которой легко следить: нумерованный список (его слово), заголовки разделов.
  Номера после переноса пересчитывает сам Obsidian — это поведение платформы, не плагина.
- Без пустых строк, на которые тратится нажатие без видимого результата.

**Субтитры и темп**
- Субтитр — **под текстом заметки с зазором ~1 строки, от левого края текста** (его слова 2026-10-05: «приходится
  разрываться вниманием», затем «слишком близко, чуть ниже»); край — по тексту, не по плашке, мимо плашки, каретки и окна Scroller; не влез — справа снизу. Место
  выбирает страница. В панели настроек — внизу по центру. Английский, короткой фразой: `Default: Move up → only the line moves`,
  `Moving behavior → Whole tree`, `Move up → it stops at its heading`.
- Паузы в шагах не пишутся: субтитр держится по длине текста, результат нажатия — 1,7 с.
  `pause` — только когда темпа мало.
- 10–60 с. Больше контролов, чем влезает в 60 с, — второй GIF `<id>-2.gif`, не ускорение.

## Проверка записи — до того, как назвать GIF готовым

**Сверять то, на что смотрит он, а не то, что удобно мне.** 2026-10-05 я дважды объявил «этапы
синхронны», сверив подпись этапа с субтитром, а он смотрел, где полоска просмотра стоит против
границ блоков, — и рассинхрон был. Каждый пункт ниже — замечание, которое он поймал сам:

| Проверка | Чем | Его замечание |
|---|---|---|
| Длина GIF = время записи | `ffprobe -show_entries format=duration` против `ok: … с`, расхождение ≤ 0,5 с | видео отставало от полосы на 3 с |
| Полоска доходит до границы блока в момент, когда он загорается | полоса по кадру в секунду столбиком: `fps=1,crop=960:42:0:ih-42,tile=1x<сек>` | «этап 2 начался на трети его полоски» |
| На старте каждого этапа на экране — его субтитр, а не прошлого | кадры вокруг смены этапа | «ещё показывал этап 1» |
| Этап плагина начат включением функции | лист кадров: переключатель off → on | «почему начался Jump by word» |
| На камеру не выключается ничего постороннего | лист кадров этапа | «потратил время на отключение контролов» |
| Рамка `spot` на нужном узле и раздел виден целиком | кадр рамки; тёзки (`Status` в предпросмотре и в порядке Fields) — частая ошибка | рамка трижды встала не туда |
| Плашка у каретки / слева от строки, не в стороне | кадры нажатий | «где-то в стороне» |
| Подсветки, гало, фона строки нет там, где их не просили | лист кадров | «убери подсветку строки» |

- Код выхода 0 и строка `ok: … с, … МБ` (до ~5 МБ).
- Лист кадров: `ffmpeg -i <gif> -vf "fps=1/1.5,scale=480:-1,tile=4x8" -frames:v 1 sheet.png`
  и посмотреть глазами: нет отката на экране, полоса меняется на входе в настройки,
  подсветка и плашка на нужных строках, нет посторонних окон.
- Вокруг одного нажатия — кадры подряд (`trim=start=…:end=…`, `fps=6`, `tile`): плашка
  раньше правки, подсветка в том же кадре, что и правка.

## Ловушки (купленные в этой сессии)
- Рамка `spot` на заголовке группы платформы (`Binder (custom insert commands)`) обводит контейнер выше экрана — ставить её на строку таблицы (`spot Smart bracket #1`).
- `spot` и щелчок сразу за ним: окно открывается раньше, чем прочитана рамка, — `pause 2000` после субтитра рамки.
- Окно панели с окном внутри (`Add a Field`, карточка Smart Rules, раскрытая подсказка) мелко в 560 px — `room 400` (высота = низ заметки + room + 110).
- Субтитр в конце этапа сменяется следующим без паузы — `pause 2200` после него.
