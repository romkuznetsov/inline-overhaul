# Оформление репозитория inlineOverhaul

Один принцип важнее остальных: **эти файлы читает человек, который плагин ещё не
поставил.** Он пришёл по ссылке, у него полторы минуты, и он решает — ставить или
закрыть вкладку. Всё остальное в этом файле выводится отсюда.

Второй принцип: **у каждого документа одна работа.** Документ, который одновременно
учит, объясняет и перечисляет, не делает ни одного из трёх. Разделение — в
[`references/docs-map.md`](references/docs-map.md).

## Когда это применяется

| Применяется | Не применяется |
|---|---|
| `README.md` | `CLAUDE.md` |
| `CHANGELOG.md` | `docs/PRD_*`, `docs/AUDIT_*`, `docs/CODE_REVIEW_*` |
| `FEATURES.md` | `docs/SESSION_END.md`, `docs/OWNER_REMARKS*`, `docs/AWAITING_OWNER_CHECK*` |
| `instructions.md`, `docs/tutorial.md`, `docs/settings.md`, `docs/showcase.md` | `docs/archive/**` |
| `CONTRIBUTING.md`, `SECURITY.md`, `.github/**` шаблоны | `docs/LESSONS.md`, `docs/OPEN_QUESTIONS.md`, `docs/REMAINING_WORK.md` |
| тексты релизов на GitHub, баннеры версий | `tests/**`, `tools/**` |

Рабочие документы — внутренние. Их не надо причёсывать, и правила тона на них не
распространяются.

## Пять правил, которые нарушаются чаще всего

Если читать только один раздел — этот.

1. **Гифка раньше объяснения.** В `README.md` первая иллюстрация стоит до всякой
   прозы о возможностях. Человек должен увидеть, что плагин делает, а не прочитать.
2. **Янтарь встречается один раз на изображение.** Второй янтарный акцент гасит
   первый. Подробности — [`references/brand.md`](references/brand.md).
3. **Справочник не уговаривает.** В `FEATURES.md` и `docs/settings.md` нет слов
   «удобно», «мощный», «просто». Там перечень: что это, где лежит, что по умолчанию.
4. **`README.md` не растёт.** Всё, что длиннее экрана и не нужно в первую минуту,
   уезжает в `docs/` со ссылкой. Предел — примерно 150 строк.
5. **Раздел `## <версия>` в `CHANGELOG.md` — то, что увидит человек в Obsidian.**
   Его читает окно «что изменилось» после обновления. Формат заголовка менять
   нельзя: [`references/changelog-and-releases.md`](references/changelog-and-releases.md).

## Знак

Два знака: **словесный** — основной, и **пиктограмма `[[#iO]]`** — только для
квадратных мест, где название не показать (фавикон, карточка плагина, аватар). Файлы
лежат в `docs/brand/`, перерисовывать и подкрашивать их нельзя.

```html
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="docs/brand/io-wordmark-dark-anim.svg">
  <img alt="inlineOverhaul" src="docs/brand/io-wordmark-light-anim.svg" width="560">
</picture>
```

Каретка в анимированной версии мигает раз в 1,6 с и замирает у тех, кто отключил
анимации в системе. В местах, где анимация неуместна или не поддерживается —
статические `io-wordmark-{light,dark}.svg`. Где нужен квадрат — `io-mark-{light,dark}.svg`,
и не мельче 32 px. Полный список файлов и палитра — в
[`references/brand.md`](references/brand.md).

## Структура README — порядок фиксированный

1. Шапка: знак, одна строка описания, бейджи — по центру
2. Демонстрация: одна гифка, до всякой прозы
3. Что это: два-три предложения и настоящий пример строки в блоке `markdown`
4. Предупреждение о бете — `> [!WARNING]`, пока версия ниже `1.0.0`
5. Установка: BRAT, по шагам
6. Что умеет: четыре-пять возможностей, у каждой гифка
7. Куда дальше: таблица ссылок на документы
8. Требования, сборка, лицензия

Развёрнуто, с шаблоном — [`references/readme.md`](references/readme.md).

## Тон

Как в существующих документах проекта — он выдержан, и менять его не надо:

- второе лицо, настоящее время: «Add a Field and two commands appear»;
- путь к настройке жирным со стрелкой: **Keyboard → Smart Enter**;
- идентификаторы в `code`: `#todo`, `[[Project A]]`, `default.js`;
- термины панели с заглавной: Field, Value, Tag Bars, Prefix, Separator, Transform,
  TagWheel;
- **названия элементов интерфейса — как в самом Obsidian**, то есть первое слово с
  заглавной, остальные строчные: `Community plugins`, не `Community Plugins`;
- без восклицательных знаков; предупреждения конкретные: «Back up your vault before
  installing», а не «Осторожно!»;
- эмодзи только внутри примера строки, где они часть синтаксиса.

Подробности и словарь — [`references/voice.md`](references/voice.md).

## Чего не делать

- не перерисовывать знак, не менять его цвета, не ставить на фотографию;
- не использовать логотип Obsidian — это их товарный знак, у стороннего плагина его
  быть не должно, и правила каталога это отдельно запрещают;
- не добавлять второй акцентный цвет к янтарю;
- не писать «This is a plugin that…» — ни в описании репозитория, ни в манифесте:
  каталог Obsidian это отклоняет;
- не собирать в README таблицы шире четырёх колонок — на телефоне они уезжают;
- не вкладывать `> [!NOTE]` и прочие выноски друг в друга и не ставить подряд: GitHub
  их не соберёт, и смысл выноски теряется;
- не заводить второй рассказ о выпуске: текст живёт в `CHANGELOG.md`, всё остальное
  на него ссылается.
