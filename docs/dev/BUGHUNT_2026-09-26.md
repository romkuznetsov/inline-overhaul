# Прогон с чистого листа 2026-09-26, ночь — перечень дефектов на следующую сессию

> **Что это.** Его задача ночью 2026-09-26: «я хочу, чтобы ты в новом vault
> оттестировал весь функционал плагина с чистого листа (т.е. включая добавление
> новых fields и values, yaml properties и т.д.) и сформировал перечень
> выявленных багов… В этой сессии только формируй перечень работ, они будут
> выполняться в следующей сессии». **Кода эта сессия не меняла ни строки.**
>
> **Как собрано.** Сборка `0.10.0` (HEAD `7c5e5ec`, `npm run install:test -- <пустая папка>`),
> чистый vault без `data.json` — стартовый набор Status, Priority, Due, Project; свой
> профиль Obsidian 1.13.7, тема по умолчанию. Obsidian поднимался процессом с портом
> отладки, Playwright цеплялся по CDP — тот же приём, что `tools/obsidian_bench.js`,
> но с пустым vault. Нажатия — настоящие (`keyboard.press`), панель — настоящий DOM
> окна настроек. Пять срезов, четыре из них параллельными экземплярами Obsidian:
> команды полей и tagWheel; Navigation; Keyboard; Transform и YAML; панель настроек
> и слой Fields. **Каждая находка воспроизведена дважды.**
>
> **Рядом лежит ревизия кода той же ночи** — `docs/dev/AUDIT_2026-09-26.md` (коммит
> `3e13de1`). Где находка совпадает с её строкой, это сказано в колонке «Связано»;
> делать такую строку один раз.
>
> Адреса — имя функции и файл, где он известен, а не номер строки (У-145). Где
> места в коде нет, его находит первый шаг починки — стенд.

## 0. Как исполнять

1. **Каждая строка — сперва воспроизведение, красное на нынешнем коде.** Для
   редактора — сценарий в `SCENARIOS` `tools/obsidian_bench.js` (строку искать
   последним совпадением) или `tools/line_bench.js`; для панели — проверка набора.
   Не воспроизвелось на его `data.json` — строка закрывается словом «не
   воспроизвелось» и командой, которой это снято.
2. Затем починка, мутация (правило 6), семь шагов, **один кусок — один локальный
   коммит**. Под З3 — с измеренным нулём (В-120) и строкой в `Z3_EXCEPTIONS.md`.
3. **Порядок: сперва корни раздела 1** — каждый закрывает несколько строк
   раздела 2 разом, и чинить строки поодиночке до корня — значит чинить одно
   правило в трёх местах (правило 72). Потом критичное → серьёзное → мелкое.
4. Строки с пометкой **«решение»** ждут его ответа (раздел 3, вопросы
   `В-235`…`В-245` в `OPEN_QUESTIONS.md`) и не блокируют остальных.
5. Всё, что меняет видимое, — тест в `test-vault/testing.md` и строка в
   `AWAITING_OWNER_CHECK.md`.

Тяжесть: **К** — теряются данные человека или функция недоступна;
**С** — неверный результат, заметный в работе; **М** — мелочь, текст, вид.

## 4. Что проверено и работает

- **Команды полей:** круг `next`/`previous` у Status, Priority, Due, Project на всех
  формах строки; frontmatter пропускается; отмена — по шагу на команду; большая
  заметка (3000 строк) — без задержки.
- **tagWheel:** стрелки, Enter, Esc, Tab на правый блок, `next-block` между блоками,
  отмена сессии одним Ctrl+Z; выключение плагина при открытой панели возвращает строку.
- **Navigation:** Move up/down (Line only, Whole tree, Jump over neighbor trees),
  прокрутка Center/Top/Bottom, Jump up/down по заголовкам и строкам, Jump left/right
  всех шагов, отмена каждого движения одним шагом.
- **Keyboard:** Ctrl+A во всех режимах, Smart paste (счёт, продолжение, `1)`, чекбоксы),
  Binder (окно, дубль, пустая строка), `to hotkeys`.
- **Advanced:** Save a backup и Restore a backup (с `… Autogenerated.md` перед заменой).
- **Language:** перевод применяется сразу после выбора.

## 5. Что не пройдено

Placement modes и Prefix priority по существу; Autosave; Developer logging;
перетаскивание Field мышью (проверено стрелками); Color custom tags; Cursor jump
highlight; Tag Bars; щелчок по нарисованной ссылке (мой щелчок не доходил и до
обычной ссылки — стенд не годится, его сценарий `link-click` работает на его vault);
тема Minimal (его сторона сверки).
