# Проверки

## После правки любого документа

- [ ] Янтарь на каждой картинке встречается один раз.
- [ ] Бейджи одного стиля, не больше четырёх в строке.
- [ ] У каждой гифки задана `width` и написан `alt`.
- [ ] Ссылки относительные; якоря собраны по правилу GitHub (пунктуация выброшена,
      пробелы в дефисы).
- [ ] Выносок не больше двух, не подряд, не вложенных.
- [ ] Названия контролов совпадают с панелью — включая капитализацию.
- [ ] Новый документ добавлен в таблицу «Where to go next» в README.
- [ ] `README.md` не длиннее ~150 строк.

## Перед выпуском

- [ ] `## Unreleased` переименован в `## <версия>` — **одним словом, без скобок и
      даты в заголовке**, иначе `gen_release_notes.js` не найдёт раздел и сборка
      упадёт.
- [ ] Под заголовком версии стоит строка с датой; ссылка на сравнение — только если
      тег предыдущей версии существует (`git tag`).
- [ ] Пункты нумерованы сквозь все разделы версии, каждый в одну строку.
- [ ] Версия поднята в `manifest.json`, `package.json` и `versions.json`
      (`node tools/build/set_version.js <версия>`).
- [ ] Тег и имя релиза равны версии **без `v`**.
- [ ] В релизе три отдельных файла: `main.js`, `manifest.json`, `styles.css`.
- [ ] Тело релиза написано для людей и ссылается на якорь в `CHANGELOG.md`.
- [ ] Ломающие изменения — первым блоком `> [!IMPORTANT]`.
- [ ] Баннер версии лежит в `docs/media/version-banners/<версия>.jpg`.
- [ ] `npm test` проходит — в том числе `release_notes_tests.js` и `docs_terms_tests.ts`.

## Разово, руками — этого Claude Code сделать не может

- [ ] **Social preview.** Settings → General → Social preview → Upload an image →
      `docs/brand/social-preview.png`.
- [ ] **Описание репозитория.** Шестерёнка справа от About:
      `Keep tags, links and dates on the same line as the thought. An Obsidian plugin
      for keyboard-first inline fields.`
      Совпадает со строкой в шапке README и с `description` в манифесте.
- [ ] **Topics.** `obsidian`, `obsidian-plugin`, `obsidian-md`, `pkm`, `markdown`,
      `productivity`, `tags`. Только строчные буквы, цифры и дефисы; до 20 штук.
- [ ] **Галочки в About:** Releases оставить, Packages снять.
- [ ] **Проверить живую страницу:** мигает ли каретка в шапке README. Если нет —
      заменить анимированные файлы знака на статические.
- [ ] **Community Standards** (`/community`): README, LICENSE, CONTRIBUTING,
      SECURITY, шаблоны issue и PR — все галочки на месте.

## Что легко упустить

**`CLAUDE.md` лежит в корне и виден каждому, кто открыл репозиторий** — 220 КБ
рабочих заметок вторым файлом после README. Это не ошибка оформления, но на
впечатление влияет. Если решишь убрать с глаз, `.github/CLAUDE.md` тоже читается
Claude Code, а в корне не мозолит глаза.

**`docs/` пополам рабочее и пользовательское.** `AUDIT_*`, `PRD_*`, `OWNER_REMARKS*`,
`SESSION_END.md` стоят рядом с `showcase.md`. Человек, открывший `docs/`, не понимает,
что из этого для него. Разделение на `docs/` и `docs/internal/` решило бы это одним
переносом — но ломает ссылки, поэтому делается отдельной задачей, не попутно.
