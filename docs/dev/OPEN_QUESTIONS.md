> **проверки**, — в `docs/dev/AWAITING_OWNER_CHECK.md`; замечания по ходу

Отвеченный вопрос не удаляется, а помечается **отвечено** с датой и решением —
так видно, почему сделано именно так.

### В-148. Убирать ли из корня репозитория `.json` и `.mjs` — **отвечено 2026-09-19: «оставить как есть»**

**Его вопрос под `N9`:** «в корне много файлов .json .mjs — можно их тоже спрятать в
подпапки?»

**В корне их шесть, и четыре из шести обязаны там лежать** — это требование тех
инструментов, которые их читают, а не мой выбор:

| Файл | Кто его читает из корня |
|---|---|
| `manifest.json` | Obsidian и BRAT: по нему они узнают версию и имя плагина |
| `versions.json` | то же: какая версия плагина к какой версии Obsidian |
| `package.json` | npm — он ищет его рядом с собой, из другой папки команды падают |
| `package-lock.json` | там же, где `package.json`, иначе он не читается вовсе |
| `tsconfig.json` | **может переехать**: компилятору пути передаются флагом |
| `eslint.config.mjs` | **может переехать**: линтеру тоже |

**Цена переезда двух движимых — не в правках, а в флагах.** В репозитории на них
ссылаются три файла: проверка типов, документы и команды в `package.json`. После
переезда каждая команда получает флаг с путём, а редакторы (VS Code и его расширения)
перестают находить их сами: они ищут ровно в корне. Выигрыш на странице GitHub — две
строки из четырнадцати.

**Варианты:**

1. **Оставить как есть** (рекомендую). На странице репозитория в корне видно
   **двадцать записей** — посчитано `git ls-files`, а не на глаз: шесть папок
   (включая `.claude` и `.github`), шесть заметок `.md`, два файла git и шесть
   служебных, из которых четыре переехать не могут.
2. **Спрятать `tsconfig.json` и `eslint.config.mjs`** в папку (например, `config/`).
   Две строки меньше, флаг в каждой команде и редакторы без автонастройки.
3. **Убрать из корня ещё и `CLAUDE.md`** — это мой рабочий файл, ему в корне делать
   нечего; проверю, что инструмент читает его из подпапки, и перенесу.
