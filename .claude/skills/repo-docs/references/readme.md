# README

`README.md` — не руководство. Это посадочная страница: человек решает по ней, ставить
плагин или нет, и уходит по ссылке за подробностями.

## Что выше сгиба

Первый экран (примерно до первой прокрутки) несёт ровно это, в этом порядке:

1. **знак** — `<picture>` с анимированной версией;
2. **одна строка описания** — меньше 120 знаков, **та же самая**, что в поле About
   репозитория и в `description` манифеста. Три разных описания одного плагина — первое,
   что выдаёт непричёсанный проект;
3. **бейджи** — четыре, одного стиля;
4. **гифка** — до всякой прозы.

Так устроены README, которые считаются образцовыми: у `httpie` анимация стоит выше
любого текста, у `obsidian-dataview` четыре примера со скриншотами идут раньше
объяснений. Причина простая: показать быстрее, чем рассказать.

## Длина

Предел — примерно **150 строк**. Он не из спецификации, а из наблюдения: всё, что
длиннее, человек не читает, а листает мимо.

Признак, что пора выносить раздел в `docs/`: раздел нужен не в первую минуту, а на
второй день. Так ушли настройки по вкладкам — им место в `docs/SETTINGS.md`, а не в
README.

## Гифки

**В `README.md` их сейчас нет ни одной — его слово 2026-09-20:** «это старые
gif и они сделаны плохо — нужно улучшить и выложить нормально», «спрячь gif, пусть
будут заглушки — ссылки на showcase.md». На месте каждой стоит строка-ссылка на
свой раздел `docs/SHOWCASE.md`. Правило «гифка раньше объяснения» с этого дня
читается как «показать раньше, чем объяснять», и пока показывать нечем — ведёт
ссылка. Правила ниже действуют с того дня, как он принесёт новые записи.

В `docs/media/showcase/` тридцать записей. Правила:

- **не больше пяти на README.** Больше — страница превращается в мельтешение и
  весит столько, что на медленной сети не открывается;
- **ширина задана явно**: `<img src="docs/media/showcase/pkm-cycle.gif" width="720" alt="…">`.
  Без неё гифка растягивается на всю колонку;
- **подпись говорит что происходит, а не как называется команда.** «A status tag
  cycling through its values in place» — да. «Field cycle increase» — нет;
- **`alt` обязателен** и описывает содержимое, а не повторяет заголовок;
- в README идут только записи с настоящим Obsidian. Какие из тридцати сняты с
  живого редактора, а какие являются анимированными схемами, сказано в
  `docs/SHOWCASE.md`.

## Ссылки

Только относительные: `FEATURES.md`, `docs/SHOWCASE.md`. GitHub сам подставит нужную
ветку, и ссылка не сломается в клоне.

Якоря GitHub делает так: буквы в нижний регистр, пробелы в дефисы, **остальная
пунктуация выбрасывается**. `## Install & setup` даёт `#install--setup` — два дефиса,
потому что `&` исчез, а оба пробела вокруг него остались. Это самая частая поломка
ссылок, написанных руками.

## Чего в README нет

- инструкции по вкладкам настроек — они в `docs/SETTINGS.md`;
- полного списка команд — он в `FEATURES.md`;
- истории изменений — она в `CHANGELOG.md`;
- благодарностей, планов, дорожных карт — пока проект в бете, они шум;
- значков вида «made with love» и разноцветных бейджей вперемешку.
