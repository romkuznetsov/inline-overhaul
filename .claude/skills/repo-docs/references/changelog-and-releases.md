# CHANGELOG и релизы

## Главное ограничение — его нельзя нарушить

`tools/build/gen_release_notes.js` режет `CHANGELOG.md` на разделы **регулярным
выражением `^##\s+(\S+)\s*$`**: заголовок версии — это `##`, один пробел и **одно
слово без пробелов**, начинающееся с цифры. Раздел своей версии уезжает в сборку и
показывается человеку в окне «что изменилось» после обновления; если его нет, сборка
падает с ошибкой.

Отсюда:

```markdown
## 0.4.0          ← так, и только так
## [0.4.0] - 2026-09-19   ← сборка это НЕ увидит
```

Дата и ссылка на сравнение ставятся **строкой под заголовком**, а не в него:

```markdown
## 0.4.0

_2026-09-19 · [все изменения с 0.3.2](https://github.com/romkuznetsov/inline-overhaul/compare/0.3.2...0.4.0)_

### Added
```

Эта строка попадает в окно «что изменилось» вместе с разделом — и это правильно:
человек видит дату выпуска и может перейти к полному сравнению.

> [!IMPORTANT]
> Если когда-нибудь понадобится полный формат Keep a Changelog с заголовком вида
> `## [0.4.0] - 2026-09-19`, меняется ровно одна строка — регулярное выражение в
> `parseChangelogSections` на `^##\s+\[?(\d[^\]\s]*)\]?(?:\s+-\s+\S+)?\s*$` — и
> правятся `tests/regression/release_notes_tests.js`. До тех пор заголовок остаётся
> односложным.

## Шапка файла

```markdown
# Changelog

All notable changes to this project are documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/);
versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
Release dates are ISO 8601, `YYYY-MM-DD`.

## Unreleased
```

`## Unreleased` всегда сверху и всегда есть, даже пустой. Сборка его пропускает
намеренно — у него нет номера, с которым его можно сравнить. Между выпусками
сделанное копится там; в коммите выпуска раздел переименовывается в номер версии, и
под заголовок дописывается строка с датой.

## Сводка выпуска

**Её не пишут руками — её собирают.** Команда:

```
node tools/build/gen_release_notes.js --summaries
```

Сводка стоит коллаутом `> [!NOTE]` под строкой с датой, и она — первое, что человек
видит в окне «что изменилось» и на GitHub. Форму задал заказчик 2026-09-22: «в
changelog мне не нравится как сделан коллаут — куча склеенного текста. Нужно сделать
более общее overview того, что сделано, и сделать это более читаемым — буллиты,
полужирный шрифт у ключевых слов, суммаризировать инфу».

```markdown
> [!NOTE]
> 🐛 **5** bug fixes · 🎨 **5** changes you can see · ✨ **6** new things
>
> **New in this release**
> - **The scroller can label Values the way you print them**
```

Числа считаются по пунктам **того же раздела**, а буллеты — заголовки пунктов со
знаком ✨. Написанное руками число стареет молча в день, когда пункт дописали;
поэтому у утверждения и его предмета один дом, а `release_notes_tests.js` требует
равенства и называет команду, которой сводку пересобрать.

Порядок родов в сводке — его порядок слов: починки, потом видимые изменения, потом
новое, потом скорость и внутреннее. Род, которого в выпуске нет, не упоминается.

## Разделы внутри версии

Keep a Changelog допускает шесть имён, и порядок именно такой:

| Раздел | Когда |
|---|---|
| `Added` | появилась возможность |
| `Changed` | изменилось поведение существующей |
| `Deprecated` | помечено к удалению |
| `Removed` | удалено |
| `Fixed` | починен дефект |
| `Security` | уязвимость |

Пустые разделы не пишутся. **`Internal` и `Performance` — наши, за пределами
спецификации.** Они полезны: человеку видно, что выпуск не пустой, даже когда на
экране ничего не изменилось. Ставятся последними, после шести стандартных.

## Форма пункта

**Решение заказчика 2026-09-19, держится `tests/regression/release_notes_tests.js`:**
пункт нумерованный, в одну строку, лаконичный, нумерация сквозная через все разделы
одной версии.

Нумерация сквозная — чтобы было видно, сколько всего изменилось. Одна строка —
потому что Obsidian показывает одиночный перенос строки переносом, и свёрстанный
абзац приезжает человеку лестницей.

```markdown
### Added

1. **New: `Stripe direction`** — which Block gets the Stripe behind it: `Left`, `Right`
   or `Both`. `Both` by default, so nothing changes until you pick a side.

### Changed

2. **TagWheel no longer writes a value twice.** A line carrying the value of a child
   Field whose parent is not on the line got that value again in the Right Block.
```

Пункт начинается с того, **что человек увидит**, а не с того, что поменялось в коде.
Жирным — суть в одном предложении, дальше подробность. Если подробность не нужна,
одного предложения достаточно.

## Ссылки на сравнение

> [!IMPORTANT]
> Ссылка `compare/<A>...<B>` работает, **только если оба тега существуют**. На
> 2026-09-20 в репозитории один тег — `0.4.0`. Ссылка на несуществующий тег отдаёт
> 404, а мёртвая ссылка хуже её отсутствия.

Поэтому строка под заголовком версии несёт:

- **дату и ссылку на сравнение** — если тег предыдущей версии есть;
- **только дату** — если нет.

Со следующего выпуска после `0.4.0` сравнение строится всегда:

```markdown
_2026-10-04 · [все изменения с 0.4.0](https://github.com/romkuznetsov/inline-overhaul/compare/0.4.0...0.5.0)_
```

Теги без префикса `v` — этого требует каталог Obsidian, — поэтому и в ссылках их нет.

## Какой знак двигать

Правило живёт в `docs/VERSIONING.md` и здесь не дублируется. Короткая проверка:
в панели появился контрол или в палитре появилась команда — **второй знак**; всё
остальное, даже большое, — **третий**. Первый знак — день подачи в каталог Obsidian.

Связь с разделами: `Added` тянет второй знак, `Fixed` и `Security` — третий,
`Removed` и ломающий `Changed` до `1.0` идут вторым.

## Тело релиза на GitHub

Это **не** копия changelog и не второй рассказ. В `CHANGELOG.md` — постоянная
история, в релизе — письмо к тем, кто обновляется сегодня.

```markdown
## 0.4.0 — Blocks get their own text size

<одно-два предложения: что в этом выпуске главное>

> [!IMPORTANT]
> <только если что-то сломается: что именно и что с этим делать>

<гифка новой возможности, если она есть>

**[Все изменения этого выпуска →](https://github.com/romkuznetsov/inline-overhaul/blob/main/CHANGELOG.md#040)**
```

Что уместно в релизе и неуместно в `CHANGELOG.md`: инструкция по обновлению,
скриншот или гифка новой возможности, известные проблемы, благодарность тем, кто
прислал отчёт.

Якорь раздела — номер версии без точек и скобок: `## 0.4.0` даёт `#040`.

## Сборка релиза

- **Тег равен версии из `manifest.json`, без `v`:** `0.4.0`, не `v0.4.0`. Имя релиза
  такое же. Это требование каталога Obsidian, и бот проверки его смотрит.
- **Ассеты — три отдельных файла, не архив:** `main.js`, `manifest.json`,
  `styles.css`. Zip каталогом не принимается.
- **`versions.json` обновляется вместе с `manifest.json`** — в нём соответствие
  версии плагина минимальной версии Obsidian.
- **Бета через BRAT:** тег, имя релиза и `version` в released-манифесте совпадают
  до знака (`0.5.0-beta.1`). Версию беты **не коммитим в `manifest.json` на `main`**,
  иначе штатный апдейтер Obsidian подхватит её раньше времени. `manifest-beta.json`
  больше не нужен: BRAT начиная с 1.1.0 его игнорирует.
