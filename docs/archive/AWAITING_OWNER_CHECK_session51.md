### 147у. Цитата и каллаут: ни знака списка, ни задачи — **сделано 2026-09-14, ночь**

**Ваше замечание по `S41`, обе части.** Вы назвали и то, чего ждёте: «поведение
в коллауте должно быть по аналогии с хедером».

**Стенд на вашем `data.json` показал больше, чем письмо.** У вашего `#todo` свой
чекбокс, и на строке-каллауте он не просто вставал не туда — он **накапливался**
по одному на шаг: `#source [!] [ ]`, потом `#note [N] [!] [ ]`.

**Причина одна на обе части**, и это то же правило платформы, из-за которого
чинились скобки без дефиса: **задача бывает только за знаком списка**. Внутри
цитаты знака списка мы не ставим — значит и задачи там быть не может; а на
выходе из круга значений пустой левой зоне подставлялся `-`, и знак появлялся
там, где вы его не ставили.

**Стало так же, как на заголовке:**

```
> [!note] важное  ->  > [!note] #todo :: важное
                  ->  > [!note] #source :: важное
                  ->  > [!note] #note :: важное
                  ->  > [!note] важное
```

**Как проверить, за две минуты:** строка `> [!note] важное`, нажимать шаг по
`type` четыре раза подряд. Каллаут обязан остаться каллаутом на каждом шаге,
квадратных скобок значения появиться не должно, а четвёртый шаг обязан вернуть
строку к исходной. То же на `> текст`. И обратная сторона: на `> - текст`
чекбокс значения **ставится** — знак списка там ваш.

**Чем закреплено.** Проверка проходит весь круг значений, а не один шаг: по
одному шагу видно только первую половину замечания. Контроль первым: на строке
списка чекбокс значения и правда ставится. Две подмены — по одной на каждое
исправленное место — краснеют. Семь шагов из семи зелёные, обход строки на вашем
конфиге — 81 сочетание, расхождений ноль. Разбор — PRD 10.13.120.

**Строка листа:** `S41`.
