# Замечания заказчика

Куда складываются замечания по ходу проверки — по строке на замечание, до
разбора в работу. Реестр того, что ещё не проверено, — `docs/AWAITING_OWNER_CHECK.md`.

## Откуда они приходят

Три источника, и все три перечитываются каждую сессию (У-30):

1. **`test-vault/Приёмка.md`** — строки `💬` у непоставленных галочек. Основной
   источник с 2026-09-01.
2. **`test-vault/Test.md`** и **`test-vault/Test 1.md`** — свободные блоки,
   заказчик заводит новый файл, когда ему удобно.
3. Сказанное в переписке.

## Как писать

Одно замечание — один пункт. Чем точнее место, тем меньше переписки:

```
### З-1. <коротко, о чём>

- **Где:** вкладка → группа → строка. Для настройки — её id
  (`Advanced → Setting ids → Show setting ids in tips` покажет его в подсказке).
- **Что сделали:** по шагам.
- **Что получилось:**
- **Что ожидали:**
- **Консоль:** есть ли ошибка в момент находки.
```

Замечание можно писать и одной фразой — разберу и переспрошу интервью, если
непонятно, где смотреть. Пустые поля лучше догадок.

## Статусы

- `открыто` — записано, в работу не взято
- `в работе`
- `сделано` — с указанием, чем закреплено: пин, гейт, проверка прототипа
- `отклонено` — только с вашим согласием и причиной
- `не воспроизводится` — с описанием того, что именно я пробовал
- `спорит` — расходится с зафиксированным решением или прототипом, ждёт вашего
  выбора; варианты — в разделе «Расхождения»
- `нужно решение` — не правка, а проектный выбор; вынесено в интервью
