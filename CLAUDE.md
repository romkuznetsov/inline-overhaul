## Правило первое: прототип нормативен

`docs/prototype/settings_prototype.html` согласован заказчиком (Р8) и является источником истины по структуре панели, всем видимым текстам и поведению своих блоков. Открывается в браузере, работает без сборки.

Из него **выводятся**, а не пишутся руками:

| Что | Чем | Правится через |
|---|---|---|
| `src/ui/settings/schema/*.ts` | `npm run gen:schema` | прототип |
| Раздел 9 и Приложение B PRD | `python tests/prototype/update_prd.py` | прототип |
| `dist/**` | `npm run build` | исходники; **под контролем версий не лежит** с 2026-09-06 (A13) |
| `tests/prototype/v1_inventory.tsv` | — заморожен, фиксирует прошлое | не правится |

Правка сгенерированного файла руками не переживёт следующую генерацию. Хук `PreToolUse` это блокирует; гейты `gen_schema` и `update_prd` ловят расхождение, если хук обойти.

Порядок при любом изменении панели: **прототип → генерация → проверки → коммит**.

Правки в прототипе делать **функциями целиком по имени**, а не участками между маркерами (У-11).

## Проверки

```
npm run lint          npm run gate            гейты слоя настроек на заглушке
npm run typecheck     npm run gate:prototype  9 проверок прототипа + расхождения
npm test              npm run install:test    сборка в тестовый vault рядом с репо
                      npm run install:test -- "<путь>"   тот же плагин в любой другой vault

npm run gate:browser  вид панели настоящим Chromium — вычисленные величины
```

Все семь шагов должны быть зелёными; **шесть из них гоняет CI**, седьмой — руками. Проверки прототипа читают **результат рендера**, а не исходник.

**Седьмой шаг — браузер, и с 2026-09-13 он снова в CI.** Заказчик решил
2026-09-11 поставить его туда; шаг был поставлен и **уронил CI в тот же час,
оставаясь зелёным у меня**. Это У-78 ровно в лоб, и развёл «зелёный у меня» с
«зелёным у всех» сервер, а не рассуждение.

**Причину назвал журнал того прогона, а не перебор окружения** (У-176): признак
дефекта был написан через величину, принадлежащую машине, и на Linux здоровая
страница выглядела как больная. Признак переписан — сравнение идёт с эталоном с
той же страницы. Разбор целиком — `docs/REMAINING_WORK.md`, строка `Т5`; здесь
он не пересказывается (У-31).
Ставится шаг двумя командами: `npm i -D playwright`,
`npx playwright install chromium` (115 МБ в кеш машины).
`npm run gate:browser` открывает прототип настоящим Chromium и спрашивает
**вычисленные величины**: видит ли браузер открытую подсказку, во всю ли ширину
своего блока она встала, контраст текста шапки против получившейся заливки, в
одну ли строку встала подпись слайдера. Заглушка DOM не считает ни одного пикселя, и за одну неделю через неё прошли
четыре дефекта, найденные только глазами заказчика (A44, A45, шапки серым по
серому, знак `%` на второй строке).

**Гейт гоняет свои проверки дважды: на нынешнем виде и на подменах**, и второй
прогон важнее. Каждая подмена возвращает панель в то состояние, из которого
заказчик уже приносил замечание; проверка, не покрасневшая ни на одной, не
проверяет ничего. Списки подмен — `tests/browser/harness.js` для панели и `tests/browser/check_editor.js` для слоя редактора; **сколько их, говорит сам прогон**, а не эта строка: число тут стояло и разошлось с ним (У-135).

**И он открывает то, что спрятано** (У-112): переключает `Selection steps` на
`Custom` и включает заливку блоков, потому что обе строки видны только при своём
выборе, а панель открывается с умолчаниями. У каждого открытия свой контроль:
ступеней ровно пять, закрашенных сторон не меньше двух, до включения — ноль.
Пустую сторону гейт **создаёт сам** (У-113): в предпросмотрах её нет ни одной.

**С 2026-09-09 браузер открывает ещё и слой редактора**, а не только прототип.
Панель плагина в браузер и правда не поднять — её рисует Obsidian, — а слой
оформления заметки есть чистый CodeMirror, и он поднимается:
`tests/browser/check_editor.js` открывает настоящий редактор с настоящим слоем
плагина и мерит подложку блоков и оверлей скроллера числами. Строка «как это
выглядит в самой заметке — решает ваш глаз» кончала лист приёмки дважды; больше
она неверна (У-98). **Подмены там правят исходник при сборке страницы** или лист
стилей: у панели дефект жил в правилах CSS, у слоя — в коде, считающем
прямоугольники.

**Отпечаток вычисленного стиля — отдельный инструмент, не гейт**:
`node tests/browser/fingerprint.js <файл>` снимает вид каждого нарисованного
узла в пяти состояниях настроек, тот же с `--check` сверяет. Нужен он переносу
оформления в классы (У-125); золотым файлом не становится — числа зависят от
версии Chromium. `IO_GATE_EXTRA_CSS=<путь к app.css>` вкладывает в страницу
настоящий лист Obsidian: перенос **опускает** специфичность, и отвечает на это
только каскад.

**Зелёный набор отвечает на вопрос «работает ли у меня», а не «у всех»** (У-78). Число проверок здесь нарочно не названо: оно растёт каждую сессию, и в документе стареет быстрее всего (У-135). Второй вопрос задаётся клоном: `git clone <репозиторий> <чистая папка>` и прогон набора там. Спрашивать до того, как объявлять работу сохранённой: 2026-09-06 набор был зелёный, а CI покраснел на первом же push — проверка читала фикстуру, закрытую `.gitignore`. Сторож на этот класс — `tests/regression/repo_completeness_tests.js`: всё в папке фикстур обязано быть под контролем версий, и ни одна проверка не зависит от приватного снимка конфига.

**Два прогона `gate:browser` одновременно роняют друг друга.** Страница гейта собирается во временную папку машины, и она одна на все прогоны: второй процесс переписывает её под первым. Признак — падение, которое не воспроизводится следующим же прогоном. Гонять по одному.

**Все команды — из `repo/`.** Запущенный из другой папки npm ищет `package.json` рядом с собой и падает с `ENOENT`, ничего не подсказывая.

Путь в `install:test` заведён ради раздела E листа приёмки — того, что бывает один раз (чистый vault, переезд конфига версии 1, уведомление о хоткеях, второе устройство); рецепты — `docs/MANUAL_TEST_PLAN.md`, раздел 0. **Скрипт, принимающий аргумент, не должен быть цепочкой через `&&`:** аргументы после `--` npm дописывает к **последней** команде цепочки и экранирует их для `cmd`, поэтому путь с пробелами приезжает с `^` перед каждым пробелом и без кавычек — то есть относительным и несуществующим. Поэтому сборку зовёт сам установщик, а не `&&` в `package.json`.

Правила ниже, каждое стоило дефекта — разбор в `docs/LESSONS.md`, раздел A. Сколько их, говорит сам список: число тут стояло и устаревало от каждого нового урока (У-145).

1. **Проверка не подделывает плагин.** Настоящие функции берутся загрузчиком `tests/harness/plugin_internals.ts`. Подделка допустима только там, где её нельзя не делать (DOM), и обязана быть названа (У-1).
2. **Конфиг для проверки берётся из фикстуры через `migrateConfig`**, а не пишется в проверке (У-2). Свой файл гоняется через `node tools/panel_dry_run.mjs <файл>`.
3. **Если заглушка модуля меняет результат — модуль берётся синхронным `require`** перед ней (У-3). Сделано для `transform_feature.js` и `priority_strip_engine.js` (третий, `rules_markdown_builder.js`, снят 2026-09-13 вместе со служебным файлом правил).
4. **Проверка зовёт функцию плагина, а не повторяет то, что та делает** (У-4, У-7). Признак спрашивается у того, кто его поставил.
5. **Ожидание выписывается отдельно от того, из чего рисуется результат** (У-5). Пин, стоящий на открытом вопросе, слепнет, когда вопрос закрывают (У-6). Кнопку и строку искать **по тому, что они делают**, а не по месту в массиве: порядок меняется.
6. **Мутация ставится до того, как правка объявлена сделанной** (У-37). Она отвечает и на «нужен ли этот кусок правки»: по C44 половина правки оказалась вторым объявлением одного правила.
7. **Фикстура гейта обязана быть законной для проверяемого** (У-38). Гейт текстов проверял вкладку, которая у владельца этой фикстуры не открылась бы, и был при этом зелёный.
8. **Подделка, выбрасывающая обработчик, доказывает наличие кнопки и молчит про то, что кнопка делает** (У-43). В гейте Г20 `onClick` у подделки ничего не запоминал — и «?» у заголовка группы четыре захода считался сделанным, пока заказчик не нажал на него.
9. **Движок гоняется тем же порядком шагов, каким его заводит плагин** (У-42). Разбор TagWheel на заметке правил без `applyOrderToRules` даёт пустую панель в обе стороны — и это выглядит находкой.
10. **«Не работает, а гейт зелёный» во второй раз — читать код платформы** (У-44). `app.js` Obsidian лежит в `%APPDATA%/obsidian/obsidian-<версия>.asar`, архив разбирается двадцатью строками на Node. Так за один вечер объяснились два замечания, три и пять заходов считавшиеся непроверяемыми.
11. **Заглушка не бывает добрее браузера** (У-45). Операция, переносящая узел, обязана отцеплять его от прежнего родителя, иначе узел остаётся в дереве дважды: `insertBefore` в заглушке три захода держал пин на три несуществующих контрола.
12. **Фикстура, в которой два имени совпадают, слепа к их расхождению** (У-47). Круговой обход конфиг-заметки проверялся на конфиге, где подпись Field равнялась ключу, — и не видел, что применение ищет Field по подписи. У заказчика подпись отличалась, и каждое применение плодило пустой Field.
13. **Фикстура, минующая нормализацию, проверяет функцию, которой нет в продукте** (У-55). Конфиг порядка приходит в движок через `parseOrderConfig`, а тот досыпает в `labels` сам ключ; проверка отдавала `labels` напрямую, ветка вывода имени дочернего Field была недостижима, и шесть утверждений держали мёртвый код.
14. **Пин по строке исходника зелен и у функции, которую никто не кормит** (У-56). Вопрос к каждому такому пину: **кто подаёт сюда значение и есть ли пин на подачу**. Режим `End of your text` не работал ни у кого восемь заходов — пин сверял строку про «configurable separator1» и молчал про то, что разделитель до неё не доезжает.
15. **Пин, написанный по поведению заплатки, охраняет заплатку** (У-58). Утверждение «у строки без своего значения один рельс» было верным девять заходов и закрепляло не функцию, а обрезку, которая её ломала. Пину, который считает **количество**, задаётся вопрос: что человек увидит, если количество останется тем же, а содержимое сменится.
16. **Свой слой не узнаёт себя по чужой разметке** (У-59). Панель TagWheel искала себя по `==…==` — это выделение Obsidian, и человек ставит его сам. Признак «это нарисовали мы» ищется в том, что пишет наш движок. **И чужое оформление на том же месте не закрашивается, а гасится** (У-66): `--text-highlight-bg` у Obsidian полупрозрачен, порядок наложения решает CodeMirror, и единственное надёжное — пометить свою строку и погасить чужое правило на ней.
17. **Тип контрола платформы задаёт, чем может быть умолчание** (У-60). `SettingColorControl` принимает только `HexString`, и «пусто = взять у темы» в значение не влезает — смысл живёт на шве, а не в значении.
18. **Согласованный сам с собой разбор бывает согласованно неверным** (У-61). `path.split("")` вместо `split(".")` в прототипе жил месяцами: писалось и читалось одинаково, и все девять проверок были зелёными. Сломалось на первой паре, где путь одной настройки — начало пути другой. Признак, что пора смотреть: появилось второе имя, начинающееся с первого.
19. **Перепись по списку файлов проверяет список, а не предмет** (У-85). Пин сводил обе стороны — каждый ключ спрашивается, каждая строка нужна, — и обе стороны смотрели в один рукописный список из четырёх файлов. Сообщений оказалось вдвое больше: половина плагина говорит не тем вызовом, который искали. Предмет, который может завестись в любом файле, переписывается **сплошным обходом**.
20. **У бюджета обязан быть положительный контроль** (У-88). Верхнюю границу лучше всех выполняет тот, кто не делает ничего: обе первые версии гейта бюджета были зелёными и мерили пустоту — сначала время броска 58 исключений, потом узлы панели, на которой ничего не отрисовано. Второе измерение обязано быть **больше нуля**, а падение внутри замера — ронять гейт, а не глушиться.
21. **Гейт, объявленный в документе, может не существовать в коде** (У-87). Г1–Г5 стояли в разделе 12 «с фазы 1» и пять фаз стерегли только прототип, а не `src/ui/settings/**`. Проверять надо **вывод** `npm run gate`, а не таблицу: таблица описывает намерение.
22. **Набор проверяет исходники, а у человека стоит сборка** (У-89). `plugin_internals.ts` читает `main.js` из корня, где `./src/...` разрешается всегда; у человека лежит плоский бандл, и там не разрешается никогда. 2026-09-07 это стоило плагина без единой команды при 51 зелёной проверке. Отвечает на второй вопрос `tests/regression/bundle_onload_tests.ts`: берёт `dist/main.js`, зовёт `onload` и сверяет список команд со списком из исходников. **Признак заранее:** в сборке есть `require`, аргумент которого не литерал — esbuild разрешает только литерал.
23. **Заглушка, годная по своему же признаку, делает загрузку недостижимой** (У-90). Заглушка реестра команд из четырёх пустых функций удовлетворяла `hasValidCommandRegistry`, и синхронная вторая попытка `require` за ней не выполнялась никогда. Заглушек в `main.js` больше нет ни одной, и это запрет: заглушка на месте модуля означает не «переживём отказ», а «работаем наполовину и молчим».
24. **Своё правило о чужой разметке обязано быть правилом платформы** (У-91). Чекбокс в плагине был «скобки с любым непустым содержимым», а Obsidian считает задачей скобки **ровно с одним знаком** — `\[(.)\] ` в `app.js` 1.13.7. Первая пара скобок за буллитом снималась как чекбокс, и `- [test-transform] test1 test2` теряла текст человека; тем же написанием Transform съедал явное имя новой заметки. Правило жило в **72 местах в трёх расходящихся написаниях**, и 53 проверки были зелёные: ни одна фикстура не подавала скобки, которые чекбоксом не являются (У-47). **Откат по одному файлу поведение не ловит** — пока хоть одно место узкое, текст выживает, — поэтому широкое написание запрещено сплошным обходом в `bootstrap_loader_tests.js`, а поведение спрошено и у исходников, и **у сборки**. Вопрос, которым это ловится: а что об этом думает сам Obsidian.
25. **Переезд кода двигает и утверждения о нём** (У-94). Когда код уходит из файла, каждое утверждение, читающее **текст** этого файла, обязано ответить, где его предмет теперь. `assertTrue` краснеет сам; **запрет молчит** — он зелен именно потому, что искать стало нечего. Ищется не по именам, а совпадением образца: у каждого утверждения спрашивается, в каком файле его регулярное выражение находит текст. Совпало больше одного файла — образец предмет не адресует, и решает человек. Перевод закрепляется мутацией **в новое место**.
26. **Мёртвое в точке входа не обязательно уезжает в сборку** (У-95). esbuild выбрасывает неиспользуемую функцию и объект-константу, но оставляет класс с `extends` и всё экспортированное. Поэтому цена мёртвого кода — не байты у человека, а то, что его читают: комментарии и утверждения набора начинают говорить о нём как о живом. Проверяется поиском имени в `dist/main.js` до и после.
27. **Свой разборщик кода — такое же объявление правила, и врёт он молча** (У-96). Инструмент, считающий границы объявлений для переезда, обязан иметь проверку **на симптом**: блок комментария, за которым не стоит объявления. Первая версия резала `const X = [ { … } ];` на первой фигурной скобке, и объяснение, купленное дефектом, осталось стоять над пустотой при 53 зелёных проверках.
28. **Положительный контроль отвечает на «приём работает», а не на «приём применён»** (У-92). Сверка копии с вынесенным модулем ломала резолв модуля вокруг вызова — приём точный, и контроль при нём был: «пока резолв сломан, модуль не находится». В тот же день `require` переехал на загрузку файла, приём перестал действовать, и сверка начала сверять **модуль сам с собой**: зелёная, с отчётом «копия равна модулю», при неверном утверждении дважды. Контроль остался верным — он стоял на своей стороне сравнения и молчал про вторую. **У проверки, которая сравнивает две реализации, мутация нужна в каждую сторону**, и до того, как правка объявлена сделанной (У-37). Признак: обе сравниваемые стороны достаются из одного места — тогда «равны» получается само.

29. **Пометка «мимо истории» не защищает чужие ступени отмены** (У-97). `addToHistory.of(false)` обещает не заводить **свою** ступень — и только это. Изменение документа случилось, прежние ступени переносятся через него, удалённое из них пропадает, а ступень без изменений выбрасывается совсем. Слой, рисующий поверх текста человека, обязан писать **только различие** (`lineDiffChange` в `tagwheel.js`) или не писать в документ вовсе. Признак: свой слой пишет в документ то, чего человек не набирал.
30. **«Проверить нечем» — это оценка, а не факт** (У-98). Прежде чем написать «остаётся за глазами», спросите цену обратного: пакет истории отмен (`@codemirror/commands`, та же реализация, что в сборке Obsidian) встал в набор одной командой и первым же прогоном воспроизвёл замечание заказчика, объявленное непроверяемым сутками раньше. Признак: в отчёте появился оборот «видно только у человека», «в наборе этого нет».

31. **Класс — это тоже объявление правила, и имя у него одно на весь файл**
(У-103). `io-tipslot` значил «спрятать кнопку платформы»; редактор Fields
взял то же имя под «сюда раскрывается подсказка», и шесть подсказок не
открывались вовсе при 56 зелёных проверках: заглушка DOM стилей не читает, а
гейт спрашивал, что подсказка **создана**. Ловится проверкой на симптом:
класс, который стили прячут, не может быть классом, в который что-то
раскрывается. Признак: у класса два места объявления и два разных смысла.

32. **Фикстура, которая разводит нажатия паузой, показывает половину дефекта**
(У-104). CodeMirror склеивает набранное подряд в одну ступень отмены, и
человек печатает именно подряд. Проверка истории обязана гонять **оба**
набора: с паузой и без. Признак: в фикстуре есть строка, двигающая часы
между двумя действиями человека.

33. **У проверки текста две половины: кто спрашивает и что нарисовано**
(У-108). Обход имён отвечает на первый вопрос и на второй ответить **не
может**: имя, которое зовёт другой блок, он считает живым, а имена у блоков
повторяются. Второй вопрос задаётся отрисовкой панели с каталогом, где
переведён **каждый** ключ: английского в нарисованном остаться не должно. Так
нашлось, что блок Smart Rules не получал подстановку вовсе и был английским при
любом языке. Признак: у блока есть `say` без контекста «на случай, если
подстановку не передали» — значит есть путь, на котором её и не передают.

34. **Оценка, выведенная из числа, а не из чтения предмета** (У-109). Число,
полученное командой, — ещё не вывод: у одного числа бывают разные причины, и
половина законна. Пятнадцать записей в консоль были помечены «расходится» по
количеству, а при чтении законными оказались все пятнадцать. У оценки
«расходится» обязан быть **список мест**, а не только их количество: список
нельзя написать, не открыв каждое.

35. **У положительного контроля есть свой положительный контроль: величина
обязана измениться** (У-110). Подмена, которая применилась и не сдвинула
измеряемое, читается как «проверка слепа», а сломана она сама: `width` под
`min-width` не работает вовсе. Признак — измеренное совпадает с прежним **до
точки**.

36. **Перепись предметов, которые заводятся в другом файле, — обход, а не
список имён** (У-111). Рукописный список подделок в гейте прототипа уронил его
`ReferenceError`-ом на первой же новой рисовалке. Признак: в проверке есть
массив строк, повторяющий имена из проверяемого файла, и дописывает его
человек, который вспомнит.

37. **Строка, видимая в одном состоянии, под проверку вида не попадает вовсе**
(У-112). Гейт открывает панель с умолчаниями; всё, что показывается только при
определённом выборе, надо **открыть самому**, и у каждого открытия должен быть
свой контроль. Признак: у настройки есть `visible`, и её умолчание — то
состояние, в котором строки нет.

38. **Предмет правила «когда пусто» в примерах отсутствует — его создают**
(У-113). Примеры делают полными, и правило «здесь ничего не рисуется» проверять
не на чем. Признак: утверждение звучит как «ничего не происходит», а в фикстуре
нет того, с чем ничего не должно произойти.

39. **Узел, найденный до перерисовки, к странице уже не относится** (У-114).
Панель перерисовывает содержимое целиком; второе нажатие по прежней ссылке
меняет отсоединённый узел и молчит. Контрол ищется заново перед каждым
нажатием.

40. **У одного узла бывает два пути появления, и правило вида обязано взять
оба** (У-115). Панель кладёт подсказку в свой узел, прототип вставляет её
соседом шапки; правило, написанное под одну отрисовку, чинит половину продукта,
и видно это только браузером. Признак: правило вида опирается на класс, который
ставит **одна** из двух отрисовок.

41. **Прототип нормативен по виду, а рисует панель свой код** (У-116). Правка
вида не закончена, пока не поправлены **оба** места: прототип и
`previews.ts` + `styles.css`. Спрашивается не «поправил ли я прототип», а
«сколько мест рисует то, что я поправил». Признак, что предмет видит только
одна отрисовка: правка прошла все семь шагов. Класс закрыт
`preview_parity_tests.ts` — он сверяет наборы переменных настроек обеих
отрисовок; правил стилей он не сверяет, и почему — сказано в нём самом.

42. **У большого числа спрашивается, сколько в нём мёртвого** (У-117). Прежде
чем разбирать посчитанное, проверьте, живо ли оно: две трети самого крупного
расхождения каталога (182 инлайновых стиля) лежали в мёртвой функции, которую
назначил к удалению сам PRD. После снятия разбор занял одну команду вместо
захода.

43. **Долг снимается сменой поведения, а не припиской** (У-118). Проверка,
требующая наличия объяснения, а не его слов, снимается словом над неизменным
блоком, и такое снятие хуже долга: оно тратит проверку, оставляя дефект.
Опуская число, скажите рядом, **чем** оно опущено. Признак: число упало, а
`git diff` показывает только комментарии.

44. **Правдоподобная находка своего обхода проверяется на известном примере**
(У-119). Обход — такое же объявление правила, и врёт он правдоподобно: моя
развёртка «настройка, которую никто не читает» объявила ничьими 46 живых
настроек, потому что собирала файлы рантайма **списком имён** — тем самым
грехом, о котором У-111. Контроль ставится **до** первого вывода: прогнать
обход на случае, ответ на который известен. Признак: вывод — большой круглый
список целой области; настоящие находки этого класса приходят по одной.

45. **«Одинаковая вертикаль» не отвечает на вопрос «одна ли это зрительная
строка»** (У-120). Границу зрительной строки знает платформа —
`view.moveToLineBoundary`, — а у своего виджета своя высота: `coordsAtPos` на
пузыре тега и на тексте **одной** строки даёт разный `top`. Один этот приём
стоял в четырёх местах подложки блоков и прожил заход при семи зелёных шагах,
потому что фикстура отдавала одну вертикаль на строку. Признак: правило про
перенос строки написано сравнением координат.

46. **Резать надо по границам платформы, а не по своим** (У-121). Правка про
перенос строки, написанная в терминах наших значений, не ловит перенос **внутри**
значения: `📅2026-09-09 11:14` рвётся по своему же пробелу. Признак: в проверке
стоит утверждение «в этом случае резать нечем» — спросите, что человек увидит
именно в этом случае (У-58).

47. **Правило, объявленное трижды, парной сверкой не закрыто** (У-122). Два
читателя сходятся между собой и оба расходятся с тем, кто предмет **пишет**;
сверка при этом зелёная и доказывает, что они копии друг друга. Сверять надо с
записью. Признак: у пина сверки две стороны, а объявлений правила больше двух — и
сильнее: ни одна из сторон предмет не создаёт.

48. **Подделка, не считающая того, что считает платформа, слепа к её правилу**
(У-124). Подделка `RectangleMarker.forRange` отдавала постоянную высоту, а
платформа считает её объединением строчных ящиков **краёв** отрезка — и
заказчик третий заход приходил с тем, чего набор не видел. Признак: подделка
возвращает константу там, где платформа считает от входа.

49. **Перенос вида из свойств узла в класс опускает специфичность** (У-125), и
половина переноса ломает вид молча: шорткат `padding` на узле отменяет
`padding-left: 0`, объявленный классом. Величины уводятся туда же, переменными
`--io-*`. И правило темы, проигрывавшее инлайну, после переноса может выиграть —
отвечает на это только каскад с настоящим `app.css`.

50. **Запрет, написанный по имени, слеп к безымянному** (У-126). Запрет
заглушек на месте модуля искал по семье имён и не видел шести безымянных IIFE ни
дня. Запрет пишется по **форме**; у этой формы она одна — свой `require` внутри
`try`.

51. **Контроль «в продукте есть хотя бы одно нарушение» умирает вместе с
долгом** (У-127). Положительный контроль обхода ставится на строке-примере, а не
на том, что нарушение в продукте ещё есть.

52. **Соглашение об именах умеет ослепить линтер** (У-128). `no-unused-vars`
разрешает имена с подчёркивания, а модули здесь так и называются — `__module`.
То есть указатель на мёртвое к модульным именам слеп по уговору самого проекта.

53. **Обход, остановленный на предмете, описывает предмет, а не его
вместилище** (У-129). Число зрительных строк считалось обходом до конца отрезка,
а делилась на него высота **строки** — и подложки двух блоков одной строки
вставали на разную вертикаль.

54. **Измерение, снятое сразу за правкой настройки, описывает прежний экран**
(У-130). Слой платформа рисует в фазе измерения, а её она откладывает до кадра:
`getBoundingClientRect` сразу за `dispatch` читает вчерашнее состояние. Гейт был
зелёный при шкале, которая не двигала ничего, и положительный контроль
«величина выросла» выполнялся отставанием обеих сторон. Признак: между правкой и
измерением нет ни одного кадра.

55. **У одной величины бывает два вопроса, и мера у них разная** (У-131). Высота
подложки одна на все строки, середина — у каждой своя; «правильная» мера,
поставленная сразу в оба вычисления, ломает второе условие заказчика. Признак:
одна мера кормит два вычисления, и о каждом сказано отдельное слово.

56. **Прижим, объявленный дважды, делает первый недостижимым** (У-132). То же,
что У-92, но признак свой: подмена, снимающая правило, не роняет ничего, потому
что копия ограничения стоит у того, кто правило применяет. И правило
спрашивается **прямо**, а не через следствие, у которого допуск больше эффекта.

57. **Фикстура, где высота строки кратна умолчанию, слепа к вертикали** (У-133).
Строка со ссылкой, эмодзи или высоким пузырём выше `defaultLineHeight`:
умолчание платформа мерит на пробной строке из одних букв. Признак: в фикстуре
высота блока выведена из числа строк, а в проверке есть утверждение о высоте
предмета без утверждения о его положении.

58. **Сверка «предмет выжил хоть где-то» не отвечает на «встал ли он туда, куда
относится»** (У-134). У проверки, склеивающей две стороны в один стог, два
долга: мутация **в каждую** сторону стога — иначе контроль зелен, потому что имя
лежит во второй, — и вопрос о месте, а не только о наличии. И нарезка документа
по заголовкам без ограничителя отдаёт последнему пункту всё до конца файла: он
«содержит» любое имя.

59. **Последствие, снятое с места вызова, — это гипотеза**
(У-136). «Отказ здесь значит вот что» — вывод о **вызываемой** функции, и без её тела он
не делается. `await` в пустом `catch` перед показом панели читается как «панель
откроется наполовину и промолчит», а внутри обеих функций оказалось пусто:
одна с пустым телом, вторая — синхронная работа над модулем из литерального
`require`. Гипотезой бывает не только «дефекта нет», но и найденный дефект.
Признак: в разборе есть оборот «отказ здесь значит…», а ни одной строки той
функции в нём нет.

60. **Мера дефекта видит одну его форму** (У-137). Число, которым меряется
долг, задаёт, что вы можете увидеть: тот же дефект в другой форме в отчёт не
попадает. Долг тихих отказов меряется пустым `catch` — и не видел ни дня четыре
копии тех же правил в `tagwheel_core.js`, спрятанные за одним `if`. Мера пишется
по **признаку** дефекта, а не по его последствию. Признак: у долга есть число, и
оно получено одним образцом — спросите, чего этот образец не находит.

61. **Мера, ищущая свой образец в сыром тексте, растёт от объяснения** (У-138).
Долг тихих отказов меряется пустым `catch`, и первое же объяснение к правке —
«здесь лежали четыре копии `try { … } catch (_) {}`» — насчиталось пятым
местом. Инструмент, ищущий в тексте программы, обязан знать, где код, а где
рассказ о коде: поиск идёт по маске, где комментарии и строковые литералы
стёрты. Признак: то, что мера ищет, вы пишете и словами.

62. **У своего разборщика ограничивают область ошибки, а не доказывают
правильность** (У-139). Полным был бы только разбор языка, поэтому неполнота
неизбежна — и пишется так, чтобы стоила одной строки: маска закрывает кавычку
не дальше конца строки. Первая версия бежала за парой до конца файла, и
кавычка внутри `/['"]/` стёрла `settings_backup.js` целиком вместе с девятью
настоящими местами. Заметил это **порог** рядом («находит ли обход ещё хоть
что-нибудь»), а не чтение. Признак: поиск парного знака без ограничителя.

63. **Пин, читающий текст мёртвой функции, зелен и не стережёт ничего**
(У-141). `assertTrue` на «в файле есть такая-то строка» не спрашивает, доходит
ли до неё исполнение: у четырёх пинов предметом были обёртки, которых никто не
звал с первого коммита, и все четыре были зелёные. Снимая мёртвое объявление,
спросите у каждого пина, где теперь его предмет, а у живого правила — каким
пином оно держится **на живом** пути. Признак: у пина предмет — функция, а не
путь; спросите, кто её зовёт.

64. **Контроль ставится на каждый шаг обхода, а не на его вывод** (У-142).
Свой обход — цепочка: разобрать, найти, посчитать. Один контроль на выводе
проверяет последнее звено и молчит про первые: обход мёртвых экспортов соврал
трижды — 122 ложные находки от разбора, пять живых имён в мёртвых от счёта и,
опаснее всего, **спрятанное настоящее** на однострочном `module.exports`. И у
широты та же болезнь: признак делегирования не «`if` и `return` с точкой», а
«тот же объект, и это вызов». Признак: у обхода один положительный контроль —
спросите, какой шаг он проверяет.

65. **Порог ставится на том предмете, из которого построен запрет** (У-143).
«Список расхождений пуст» бывает правдой и от того, что сравнивать было нечем.
Порог на соседнем предмете того же блока не годится — он краснеет на другой
поломке. Проверяется мутацией **в источник**: обнулить середину цепочки легко,
и от этого зеленеет любой запрет. Признак: рядом с `assert.deepEqual(<список>,
[])` стоит порог про другое имя.

66. **Смещения и правка текста считаются одними единицами** (У-144).
`Array.from(src)` режет по код-поинтам, `indexOf`/`slice` — по кодовым: на
первом же эмодзи маска своего разборщика съедает куски кода. Регулярное
выражение — такой же литерал: скобка внутри него ломает счёт скобок. Признак:
свой разборщик молчит ровно на файлах с эмодзи или regex-литералами.

67. **Число состояния живёт в прогоне** (У-145). Свежее число, вписанное в
документ, устареет тем же способом: `console.error` растёт ровно тогда, когда
молчание заменяют громким отказом. Номер строки — то же самое: предмет
адресуется именем. И число в заголовке стареет от каждого нового пункта.
Признак: в документе есть число, и рядом нет команды, которой его снять.

68. **Слепую фикстуру находит мутация продукта, а не чтение проверки** (У-146).
Сломайте в рантайме ровно то, что фикстура должна показывать, и прогоните
набор. Зелёный разводится вторым пробоем — `throw` в то же место: красный
значит «место выполняется, фикстура его не различает», зелёный — «сюда не
доходит ни один прогон» (У-56). Признак: в проверке стоит литерал, который в
продукте кто-то **строит**.

69. **Две согласные стороны не показывают, какую из них читают** (У-147).
`separator1`, равный `separator2`; `field.type`, совпадающий с типом из
порядка; подпись, равная ключу, — на таком примере переворот правила в продукте
проходит незамеченным. Стороны разводятся **нарочно**. Признак: в фикстуре две
настройки с одинаковым значением участвуют в одном решении.

   **И находки этого класса приходят пачками.** 2026-09-11 заказчик принёс
   подряд пять замечаний, и все пять оказались одним и тем же: правило написано
   так, что при совпадающих разделителях оно верно, а при разных нет. Найдя
   первое, не чините его в одиночку — **выпишите все места, где участвует та же
   пара**, и пройдите их разом: остальные придут следующим письмом.

70. **Мёртвый экспорт прячется за одноимённой живой копией** (У-148).
Обход «кто зовёт это имя» ищет имя по коду других файлов, и чужое
**объявление** он считает вызовом. `parseJsonFence` в `shared_utils.js` не
звал никто с первого коммита, а обход был зелёный: своя копия с тем же
именем стояла в `navigation_runtime.js`. Имя умерло не тогда, когда его
перестали звать, а когда сняли копию. Признак: имя, названное живым,
объявлено в репозитории больше одного раза.

71. **Уточнение заказчика — это правило, а не готовая правка** (У-149). «Тут
не важны теги и дата, а field order — любой field type может быть где
угодно» я прочёл как «у левого сегмента спрашивать левую сторону Order» — и
первая же проверка поведения покраснела: Field, только что переставленный в
другой Block, в списке стороны ещё не значится. Признак стороне не
принадлежит; вопрос был другой — значение это Field или текст человека.
Признак: правка выведена из фразы заказчика и сделана раньше, чем спрошено,
что она ломает.

72. **Починка одного объявления из трёх делает результат хуже** (У-150).
Прежде чем чинить правило, посчитайте, сколько раз оно объявлено, и
почините все объявления одним заходом либо сведите в одно. До починки пути
расходились одинаково; после починки одного они расходятся **по-разному**, и
человек получает разный результат в зависимости от того, какой кнопкой он
это сделал. Признак: правило описано словами в комментарии — ищите **эти
слова**, а не имя функции, копия несёт при себе тот же рассказ. Второй
признак: в комментарии над кодом стоит ссылка на У-32 или фраза «разошлось в
двух объявлениях» — значит копию уже находили и не свели.

73. **У подмены есть свой предмет, и его надо проверить** (У-151). Подмена —
    объявление правила, и врёт она в обе стороны: собранная строкой с лишним
    уровнем экранирования, она **расширяла** образец вместо сужения — и
    отчиталась о слепоте там, где сторож был прав. Спрашивайте у файла, что в
    нём написано после подмены, до того как читать вывод прогона. Признак:
    подмена собрана из кусков строк, а её предмет — регулярное выражение.

    **И зелёная подмена бывает верной наполовину:** если предмет узнаётся
    запасным ответом, сторож проверяет запасной вместо главного. Спросите,
    какой случай развёл бы их (у нас это оказался формат без ISO).

74. **У проверки, которая что-то открывает, обязан быть контроль «оно
    открылось»** (У-152). Двенадцать проверок применения TagWheel не открывали
    панель ни разу — движок отказывался из-за фикстуры и возвращал строку
    нетронутой, — и все двенадцать были зелёными. Признак: между вызовом входа
    и утверждением о результате нет утверждения о том, что вход сработал, а
    сообщения движка проверка глушит пустой подделкой.

75. **У догадки есть условие применимости, и пишется оно вместе с ней**
    (У-153). Эвристика «единственный разделитель на строке — это второй» нужна
    ровно там, где оба разделителя записаны одинаково; без условия она отвечала
    и при разных, объявляя значение элемента текстом человека. Признак: рядом
    имя вида `looksLike…`, а условия, при котором спрашивать нечего, нет.

76. **Среда прогона — такая же сторона сверки** (У-155). Часовой пояс, язык,
    формат чисел: там, где предмет зависит от машины, обе сравниваемые стороны
    на «удобной» машине совпадают сами собой — это У-147, только совпадающей
    стороной стало окружение. Команда писала гринвичское время, панель —
    местное, и набор был зелёный, потому что CI живёт по Гринвичу. Окружение
    задаётся **в самой проверке**, рядом контроль «оно и правда сменилось», и
    значение берётся без сезонных переходов (`Asia/Tokyo`). Признак: величину
    считает не фикстура, а машина — `new Date()`, `toLocaleString`, `path.sep`.

77. **Цена варианта считается по форме, в которой его написал я** (У-156).
    «Сделать настройкой» стоило тринадцатой строки при пределе двенадцать — и
    заказчик ответил четвёртым положением у строки, которая уже стоит: цена
    исчезла, решение осталось. Прежде чем объявить вариант дорогим, спросите,
    нельзя ли сделать его внутри того, что уже нарисовано. Признак: в разборе
    есть цена вида «ещё одна строка в панели при пределе N».

78. **Написанное плагином он обязан уметь прочесть** (У-157). У пары «собрать» и
    «разобрать» спрашивается свойство: разобрать собранное и собрать заново даёт
    ту же строку. Без него дефект разбора виден не сразу, а **накоплением**:
    доводка строки зовётся по нескольку раз подряд, и каждый круг дописывал по
    разделителю — заказчик получил `- :: :: :: :: :: 👤111` и назвал это
    артефактом. Признак: в модуле есть пара «собрать»/«разобрать», и их зовут по
    очереди больше одного раза.

79. **Правило со списком мест исполняется не фразой, а кодом в каждом из них**
    (У-158). «Field с предусловием не показывается ни в TagWheel, ни в своих
    командах» стояло в PRD, и командами не спрашивалось ни разу: правило держала
    одна копия внутри панели. Признак: в документе правило со списком мест, а в
    коде одна функция, которая его считает, — спросите, кто её зовёт.

80. **Починка объявления живёт до второго читателя** (У-159). Починив
    правило, спрашивайте не «есть ли копия», а **кто ещё отвечает на этот
    же вопрос**, и проверяйте каждого поведением. А у обхода, которым вы этот
    класс закрываете, спросите, чем похожи все его примеры: то, в чём они
    совпадают, он не проверяет. Признак: у правила есть общий дом и ссылка на
    него из второго места, а второе место считает само.

81. **Слой, прячущий чужой текст, ломает чужие ступени отмены** (У-160).
    Спрашивается не «завёл ли он свою ступень», а **что он на время убрал из
    документа**: убранное и есть чужие ступени, которые схлопнутся. Мера: после
    `Ctrl+Z` документ обязан быть состоянием, которое когда-то стояло; стенд —
    `node tools/undo_bench.js`. Признак: в примере проверки истории нет ступени,
    написанной не человеком.

82. **Наша настройка кончается там, где кончается наш узел** (У-161).
    «Действует на эти и не действует на те» разбирается не с вычисления
    величины, а с вопроса **кто рисует каждый из двух случаев**: в свой узел мы
    пишем что угодно, в чужой — ничего. Выходов два: забрать предмет себе
    целиком (и вернуть всё, что у него было от платформы, — вид, щелчок,
    наведение) или подсунуть платформе свои числа её же переменными. Второй
    зависит от того, чей узел снаружи, а этот вопрос **подделка решает
    произвольно**: на стенде вложенность переворачивалась от перестановки двух
    строк в списке расширений. Признак: настройка работает на части однородных
    объектов, и в коде у них разные ветки отрисовки.

83. **Вариант интервью — это правило продукта, и его цену считаю я**
    (У-162). Перед вопросом у каждого варианта спрашивается: во что он
    разворачивается **на его машине** — его тема, его `data.json`, его
    строки — и **что из работающего он ломает**; второе пишется в сам
    вариант. Цена проверки — один прогон: тема из `test-vault` вкладывается в
    страницу браузерного стенда перед нашим листом. Признак: в варианте
    есть «всегда», «везде», «вовсе» или «берётся у темы».

84. **Обёртка вокруг предмета совпадает с образцом и без предмета**
    (У-163). Проверка требовала полосу панели, обёрнутую в `==`, и была
    зелёной при полосе, которой не было: обёртка пустоты — это `====`, и
    образец на неё ложится. Спрашивайте у образца, что он найдёт при **пустом**
    предмете; ложится на пустоту — рядом обязан стоять контроль «предмет
    непуст», и стоять **первым**. Признак: в образце `.*` между двумя
    литералами обёртки, а правила для проверки собраны руками рядом с ней, а не
    взяты из фикстуры продукта.

85. **Новая работа, которая «заодно чинит» старый дефект, чинит его половину**
    (У-164). Режим «не прятать противоположный Block» убрал ровно тот случай
    `Ctrl+Z`, который принёс заказчик (4 → 0), и не тронул случай, где значения
    есть и в своём Block (5 → 5). Опасность была в стенде: он гонял **один**
    набор шагов — тот, которым дефект нашли, — и на нём ноль читается как
    «починено». Заметив «а заодно чинит», добавьте стенду случай, в котором
    новая работа чинить **не должна**; разница между случаями и есть граница.
    У самого стенда — контроль: прежнее поведение обязано быть красным во всех
    его случаях. Признак: число снято тем же набором шагов, каким дефект был
    найден.

86. **Поле без читателя врёт бесплатно, а платит первый читатель** (У-165).
    Имя поля — такое же объявление правила, как имя класса, и проверяется оно
    чтением **значения**, а не имени. `left` и `right` у разбора строки несли
    копии корзин узнавания `tags`/`dates`; читателя не было ни одного, и ложь
    жила тихо, пока её не спросил новый режим панели — три дефекта из одного
    корня. Признак: два поля с одинаковым значением и разными именами, и второе
    имя обещает больше первого.

87. **У лекарства есть цена, и называет её тот, кто лечит** (У-166). Починив
    вид механизмом, который действует **шире** предмета — перенос, растяжение,
    `!important`, порог ширины, — напишите рядом, что ещё теперь ему
    подчиняется, и померьте тем же прогоном. `flex-wrap` ради подсказки стоил
    заказчику всех контролов панели, уехавших под описание, и шести дней.
    Признак: починка вида сделана свойством контейнера, а не свойством
    предмета, и в объяснении есть «ради».

88. **Место находится обходом по симптому, а не чтением дорог** (У-167). Из
    строки пропал предмет, а какое место его уносит — неизвестно: не читайте
    три дороги сборки, оберните каждый экспорт и спросите у каждого вызова
    «вход нёс, выход не несёт». Двадцать строк, один прогон, точное имя
    функции; чтением до этого два захода дали двух неверных кандидатов.
    Признак: в разборе есть список «это может быть вот эта или вот эта
    функция», и ни один не проверен запуском.

89. **Правило о чужой разметке, объявленное в разборе, до экрана не доходит**
    (У-168). Починив такое правило, спрашивайте не «нет ли копии», а **кто ещё
    смотрит на тот же знак**, и в первую очередь смотрит ли на него слой
    оформления: у разбора и у отрисовки разные входы и общий предмет. Живёт
    оно в общем доме (`shared_utils`), а не в том модуле, где впервые
    понадобилось. Признак: правка сделана в разборе, а замечание было про вид.

90. **Ящик строки, её блок и написанное в ней — три разные вещи** (У-169).
    Отступ строки-заголовка Obsidian задаёт `padding`, а
    `getBoundingClientRect` отдаёт ящик **границы** — то есть вместе с ним.
    Середина того, что рисуется поверх строки, считается от **написанного**
    (ящик узла минус отступы, `getComputedStyle`); прижим «не наехать на
    соседа» — по **блоку**, отступ ему принадлежит и пуст (У-131). Проверять
    на строке, у которой ящик больше написанного, — на обычной все три
    совпадают (У-147).

91. **Подделка выбирает ту форму предмета, при которой правка работает**
    (У-170). Отступ заголовка я написал в подделке `margin`, потому что так
    сказало слово «отступ»; у Obsidian это `padding`, и правка «мерить по
    ящику узла» не двигала у заказчика ничего при зелёном гейте и трёх
    краснеющих подменах. Числа и формы для подделки чужого **обмеряются у
    чужого**: `app.css` из `obsidian-<версия>.asar` плюс тема из его vault,
    открытые тем же Chromium, — один прогон. И у подделки свой контроль на её
    предмет (У-151): спрашивать не «строка выше обычной», а «у неё есть
    внутренний отступ». Признак: свойство в подделке выбрано по смыслу слова,
    а не списано у оригинала.

92. **Цену переезда считает тот, кто знает, кто рисует сейчас** (У-171).
    Прежде чем обещать «это станет нашим узлом», спросите не «сколько мест в
    коде», а **кто это рисует**: если наши правила лишь меняют чужому узлу
    цвет, рисует чужой, и переезд означает взять на себя всё, что он делал.
    Заливка полосы TagWheel — подсветка `==…==` самой Obsidian, и меньшая
    версия такого переезда уже провалилась (B2, 2026-09-02). Цена, названная
    неверно, делает выбор заказчика недействительным: пересчитав, спрашивайте
    заново. Признак: в оценке есть число мест и ни одного имени класса.

93. **Заглушка бывает не только добрее браузера, но и строже** (У-172).
    У `dispatch` CodeMirror три формы: одно изменение, список изменений, ни
    одного изменения. Заглушка, знающая одну, объявляет остальные
    несуществующими — и проверка обвиняет продукт в том, чего он не делал.
    Список отрезков применяется **справа налево**. Признак: проверка говорит
    «продукт этого не сделал», а в браузере он это делает.

94. **Своя карта отвечает на свой вопрос, а не на мой** (У-173). Карта
    прямоугольников по строкам пикселей печатала первый и последний непустой
    знак — то есть границы **всего написанного**, — и я прочёл это как границы
    подложки. Разбор вышел про реальный, но другой механизм, и заказчик ответил
    «по прежнему не исправлена». Мерить предмет — значит искать **его
    признак**: цвет подложки, а не «непустой пиксель». Признак: числа сняты
    инструментом, писанным под другой вопрос, и в выводе нет ни одного
    упоминания предмета.

95. **Починка вида открывает следующую форму того же дефекта** (У-174). Одна
    его жалоба про подложку на длинной строке потребовала трёх правок подряд, и
    каждая была верной: пока подложка стояла не на своём ряду, не было видно,
    что кусок выбрасывается; пока он выбрасывался, не было видно, что платформа
    рисует его выделением. Починив вид, спрашивайте не «сделано ли», а **какую
    форму я только что открыл**, и отвечайте подменой починенного места на
    отказ. Признак: подмена, возвращающая прежнее поведение, краснеет на
    другом утверждении, чем то, ради которого заведена.

96. **Подмена обязана быть законной программой** (У-175). Сломанный файл
    роняет прогон раньше, чем до сторожа дойдёт очередь, и красный цвет
    перестаёт что-либо значить: `ReferenceError` вместо утверждения читается
    как «поймал», а сторож не выполнялся вовсе. Смотреть надо не на код
    выхода, а на **строку отказа** — она обязана быть тем утверждением, ради
    которого подмена заведена. Признак: в выводе `SyntaxError`,
    `ReferenceError`, `Cannot find module` или «упало при загрузке».

97. **Упало у них, зелено у меня — читать их журнал** (У-176). `gh run view
    <id> --log-failed` отдаёт падение с числами; перебор окружения у себя
    отвечает на «часто ли», а вопрос всегда «при каком условии». Два дня
    перебора и три документа с неверной причиной стоили одного такого вызова.
    И признак дефекта не пишется через величину, принадлежащую машине (край
    ящика, место переноса): сравнивать надо с эталоном, снятым на той же
    странице там, где дефекта быть не может.

98. **Правило спрашивают о предмете, а не о его вместилище** (У-177). «У этого
    Field знаки задачи бывают» — вопрос о вместилище, и он говорит «да» тогда,
    когда в слоте стоит знак человека: конец цикла уносил `[x]` со строки
    `- [x] #todo`. Спрашивать надо «этот знак есть вид значения именно этого
    Field». И вторая половина того же урока: починка, сделанная флагом
    «сохранить X», не работает там, где X снимают **до** флага — на строке без
    текста знак стирали в разборе, и правило решало судьбу того, чего уже нет.
    Признак: рядом с вопросом «бывает ли здесь наше» стоит строка, которая это
    уносит.

99. **Отрисованное окно платформы — не один отрезок** (У-179). `visibleRanges`
    CodeMirror рвётся там, где стоит замена состояния длиной **от двадцати
    знаков**; такая в плагине одна — маска панели TagWheel. Обход «по кускам,
    внутри по строкам» проходит строку дважды и рисует на ней всё по два раза:
    заказчик увидел это двумя кнопками `→`, а у подложки Blocks второй
    прямоугольник ложится на первый до точки и не виден вовсе. Номера строк
    спрашиваются у **одного** объявления — `visibleLineNumbers`. Признак: в
    коде `for (… of view.visibleRanges)` с обходом строк внутри, а в фикстуре
    нет ни одной замены длиннее двадцати знаков.

100. **Остаток обхода — не ещё один элемент** (У-180). Обход, остановившийся
    раньше конца, знает меньше, чем думал; дописанный отдельной единицей
    остаток становится числом, которое кто-то поделит. Подложка так получала
    лишнюю зрительную строку, и заказчик видел вторую полосу у конца первой.
    Признак: после цикла стоит `if (at < end) list.push(...)`, а длина `list`
    ниже делит величину.

101. **Утверждение о платформе в комментарии — гипотеза, пока не назван её
    файл** (У-181). «Obsidian ставит расширения только редакторам, открытым
    после загрузки» держало целую ветку кода и было неверно: `updateOptions()`
    обходит все листы. Цена — `RangeError` на каждый патч настроек и
    невыполнявшийся толчок к перерисовке. Проверяется грепом по `app.js` из
    `obsidian-<версия>.asar`. Признак: в комментарии сказано, что делает
    платформа, и не сказано, где это прочитано.

102. **Стенд на его конфиге не пишет его настройки литералом** (У-182). Из пяти
    стендов два были мертвы сутки: обход строки — от смены разделителя, стенд
    отмены — от переименования поля. Оба падали громко, и не видел этого никто:
    в семи шагах стендов нет. Разделитель, имя поля, идентификатор команды
    берутся **из конфига**; ключ поля в идентификатор переводит один помощник —
    `fieldCommandId` в `tools/line_bench.js`. Признак: в стенде, читающем
    `data.json` человека, есть литерал, описывающий его настройку.

103. **У платформы два ответа на один вопрос, и нужен тот, которым она
    рисует** (У-183). `moveToLineBoundary` ищет конец зрительной строки под
    правым краем редактора, а `rectanglesForRange` — тот, кто подложку
    рисует, — спрашивает, на одном ли ряду `coordsAtPos(начало, 2)` и
    `coordsAtPos(конец, -2)`. Расходятся они на знак, и этого хватает: кусок
    становится пересекающим ряды, и платформа рисует его выделением — до
    правого края окна и от левого. Ответ удобного вызова берётся подсказкой и
    признаётся по признаку предмета. Признак: два разных вызова платформы
    отвечают на одну величину, и один из них — запасной путь. И то же в
    подделке: `line.to`, которого у неё нет, обход читает как «рядов нет».

104. **Внешнее оформление строки снимается один раз, внутреннее участвует в
    сборке** (У-184). Отступ, цитата и каллаут принадлежат строке целиком:
    снимаются на входе разбора, возвращаются на выходе сборки, внутрь не
    попадают. Знак списка и задача — наоборот. Спутав их, получишь не лишний
    знак, а умножение: `> > > > > > > > #/1 :: текст`. Признак: одну и ту же
    часть начала строки и снимают, и дописывают больше чем в одном месте.

106. **Настройка человека в коде не пишется** (У-186, его слово 2026-09-14:
    «мне не нравится, что в коде есть константы, пример с `||` — этого быть не
    должно»). Литерал делит людей надвое: у кого выбор совпал с написанным,
    у того правило работает, у остальных его нет, и ни одна проверка на
    фикстуре с тем же значением этого не увидит. Разделитель, знак, формат —
    спрашиваются у настроек; умолчание объявляется **один раз**, а не
    повторяется по месту вызова. Сторож —
    `tests/regression/config_literals_tests.js`. **Долг пуст с 2026-09-15**:
    все три рода сняты, и теперь проверку роняет любое новое место. Домов у
    умолчания ровно два, оба названы в стороже поимённо и печатаются вслух —
    `DEFAULT_SEPARATORS` в `shared_utils.js` и схема панели, выводимая из
    прототипа. Признак: в коде стоит значение, у которого в панели есть
    контрол.

105. **Форма, которой не было в обходе, добавляется вместе с починкой**
    (У-185). Починив замечание, допишите в обход строку, на которой оно
    пришло, и меру по **признаку** дефекта — тем же заходом. Ждать надо не
    подтверждения починки, а пачки: обход, у которого этой формы не было,
    молчал обо всём, что с ней связано. Одно его письмо про знак списка в
    каллауте дало три дефекта, из которых он видел один. Признак: замечание
    починено, а в обходе нет строки, на которой оно пришло.

123. **Запрет, написанный по положительной охране, слеп к обратной** (У-203).
`if (mod && typeof mod.X === "function") return mod.X(…)` и `if (!mod || typeof
mod.X !== "function") return []` — одно устройство, и второе к первому запрету
не сводится. Но у обратной формы есть законный близнец — **проба платформы**
(«ответ „нет“ — это ответ»), и сплошной запрет по форме назвал бы долгом 178
мест, из которых долг — семь. Разделяет их **свойство, а не список имён**
(У-201): спрашиваемое имя обязано быть тем, что экспортирует какой-то наш
модуль; отвечает на это перепись `module.exports` всего рантайма, а не память. И
громким отказом считается не только бросок: `Notice` человеку — тоже отказ, вид
первый. Признак: запрет на устройство написан по одной из двух охран.

125. **Ширина признака меряется до того, как он станет сторожем** (У-204).
Признак, написанный по найденной копии, ловит её написание; признак,
написанный по телу, ловит весь язык. Между ними — измерение, и стоит оно один
прогон: «где вообще встречается `String(x || "").trim()`» дало **242** места в
рантайме, «имя про ключ Order, а за ним функция» — **13** (двенадцать обычных
использований), «имени про ключ Order присвоено тело дома» — **0**.
Ставить в сторож можно только третий, и у него обязаны быть **отрицательные**
контроли — строки, которые он путать не должен, — иначе широкий признак назовёт
долгом чужое и его снимут целиком. Признак: у нового запрета есть только
положительные контроли.

124. **Ноль у положительного контроля бывает не «меряли не то», а «мерить
нечем»** (У-203). У`handleSmartBackspaceKeymap` бросок на входе не покрасил ни
одной проверки из семидесяти одной, и стенда, который бы до неё достал, нет:
зовёт её нажатие клавиши у человека. Тогда водитель пишется **вместе с
починкой** — проверка, которая этот шов и исполняет, — и её обязана ронять
мутация «шов молча отвечает прежним значением». Признак: предмет — метод точки
входа или шов, у которого один звавший, и тот в раскладке клавиш.

122. **У правила без сторожа есть срок годности, и мерится он в сессиях**
(У-202). Правило «текст с обратными кавычками пишется инструментом правки
файла, а не через оболочку» стояло десять дней и было нарушено мной же: текст
уехал в `python -c` через двойные кавычки, оболочка выполнила содержимое
обратных кавычек, и в корне осталось четыре пустых файла с именами из русских
слов — а `git add -A` унёс их в коммит. Тем же разом из текста для заказчика
исчезли два имени. Сторож теперь есть — `repo_completeness_tests.js`, по форме
(пустой файл без расширения в корне), законные имена названы поимённо.
Признак: правило куплено дефектом, а сторожа у него нет — оно живёт на моей
памяти, и срок у неё кончается.

121. **Признак, написанный образцом, ловит ту запись, на которой его писали**
(У-201). Починив предикат **второй раз подряд** добавлением образца, спросите,
какое **свойство** вы на самом деле проверяете, и напишите его. Признак
делегата чинился шесть раз шестью образцами; седьмая версия спрашивает
свойство — «из тела нет выхода, кроме ответа дома и громкого отказа» — и сразу
закрыла две записи, до которых образцы не добрались. И у свойства свой
контроль: он нашёл дыру, которой признак жил с первого дня (возврат сверялся
только началом, и `return __mod.f(x) || "tag"` числился делегатом). Признак:
в предикате растёт список образцов.

120. **Зелёный пробой ничего не значит, пока не сказано, чем эта функция
исполняется** (У-200). Положительный контроль к пробою — не формальность: у
`panelFieldIdsFor` он дал **ноль** покрасневших проверок, то есть набор её не
исполняет вовсе, и зелёный первого пробоя был зелёным от тишины (У-56).
Достал до неё стенд на его конфиге — `node tools/line_bench.js panel …` с
шестью `ArrowRight`, при его настройке `Move to the next Block`. Признак:
пробой зелёный, а контроль не назвал **ни одной** покрасневшей проверки —
меряли не то.

119. **Мера, считающая объявления, обязана отличать объявление правила от
адреса** (У-199). Доставалка модуля (`return __mod;`) и ленивая сборка своего
экземпляра правила не объявляют: свести их не во что, и в долге они называют
не тот предмет. Род выводится **из формы**, и печатать форму обязан инструмент
(`node tools/rule_copy_shapes.js`), а не глаз: пятнадцать имён числились
разобранными со слов прежних сессий, и четыре оказались копией на молчаливом
ходу. Но прятать такие имена нельзя — они печатаются отдельным списком и
названы поимённо в стороже `rule_copies_debt_tests.js`. Признак: у долга есть
число, и в нём лежат предметы разного рода.

118. **Ключ правил, который пишет одна дорога, — её шов** (У-198). У ключа в
    объекте правил спрашивается не «кто его читает», а **кто его пишет**:
    `rules.dates.markers` пишут три вызова, и все три в
    `navigation_runtime.js`. Общий помощник, написанный под такой вход,
    работает у той дороги, которая его пишет, и молчит у всех остальных —
    ветка, которую он кормит, у них не исполняется никогда. Снаружи это
    неотличимо от чтения конфига: слово `rules` обещает общее. Признак:
    читателей у ключа больше одного, а писатель один.

117. **Ввод человека нормализует плагин, а не человек** (его слово 2026-09-15,
    В-118): «пользователь может вводить как угодно (`- [x]` / `[x]`), а плагин
    сам нормализует ввод». Образец — `add value`: принимается и `#tag`, и
    `tag`, сохраняется `#tag`. Отсюда следствие, которое легко спутать с
    копией: **нормализатор ввода и разборщик уже готового значения — разные
    вопросы**, и одинаковые имена у них надо разводить, а не сводить тела.
    Признак: два объявления с одним именем, и одно из них стоит на пути
    текстового поля панели.

116. **Подмена внутри одной дороги самоуничтожается** (У-196). Если значение
    идёт через функцию туда и обратно — разбором и сборкой, — равномерная
    ошибка в ней гасится, и сравнение двух дорог её не увидит **в принципе**.
    Положительный контроль обязан нарушать симметрию: ломать другую дорогу
    либо только одну половину пары. И «бьёт ли подмена в предмет» (У-151)
    спрашивается **на его настройках**: дневная ветка арифметики не
    исполняется, когда у его формата самая мелкая единица — минута. Признак:
    подмена не покраснела, а её предмет проходится дважды.

115. **Ожидание ответа ловит поломку дома и не ловит возврата копии**
    (У-195). У двух родов проверок разные предметы: ожидание правильного
    ответа зовёт дом напрямую и слепо к тому, что бывший владелец завёл своё
    тело обратно; проверка формы объявления — наоборот. Сводя копию, ставьте
    **обе**, и вторую — после мутации, которая показала дыру. Признак: вы
    свели копию и проверили сведение только вызовом дома.

114. **Сведение копий делает сверку двух дорог слабее** (У-194). Пока правило
    объявлено дважды, обход «панель против команды» силён: расхождение видно
    сразу. Сведено к одному — и он отвечает лишь на «стоит ли делегирование»:
    сломанный общий дом ломает обе дороги одинаково, и обход зелёный. Сводя
    копию, **тем же заходом** пишите ожидание правильного **ответа**, а не
    равенства сторон. Признак: в отчёте о сведении сказано «сверка зелёная» —
    спросите, что покраснеет, если сломать дом.

113. **Починка признака по одной найденной форме работу не кончает** (У-193).
    Мера копий соврала второй раз подряд и тем же способом: после У-191 она
    по-прежнему не видела форму «связать, охранить отказом, вернуть», какой
    движки под З3 берут помощников через шов. Известный ответ, на котором мера
    проверяется, — **то, что вы только что свели сами**: свели, а число долга
    не сдвинулось, значит врёт мера. Контроль нужен в двух видах: список имён
    (только уходят) **и счёт настоящих тел по каждому имени** — измениться он
    обязан ровно у сведённых. Признак: копия сведена, а долг тот же.

112. **У своей маски спрашивают, сколько она съела** (У-192). Маска сторожа
    мёртвых экспортов давала обратной кавычке искать пару до конца файла, а та
    стоит внутри регулярного выражения: обход видел 20 227 знаков из 85 362 и
    объявил ничьим живой экспорт. Мера — отношение длины маски к длине файла;
    ниже девяти десятых повод смотреть. И направление ошибки выбирается
    нарочно: пропустить мёртвое можно, назвать мёртвым живое — нет.

111. **У обращения к общему дому больше одной формы** (У-191). Мера копий
    видела `__модуль.имя(...)` и не видела ни геттера, ни «ensure»-геттера —
    честные делегаты числились копиями, и число долга было завышено на десять
    имён. Расширяя такой признак, сличайте списки до и после: имя может только
    **уходить** из копий, и ни одно настоящее тело уйти не должно. Признак: мера
    написана по одной форме предмета.

110. **Стенд на его конфиге меряет сегодняшний конфиг** (У-190). Прогон,
    покрасневший без единой правки кода, — повод посмотреть на дату его
    `data.json`, а не в код: он перенастраивает плагин по ходу проверки, и его
    правка открывает случаи, которых не находил ни один прогон. Производный
    конфиг (копия с разведёнными разделителями) собирается из его нынешнего
    файла, а не хранится. Признак: зелёное стало красным, а `git diff` пуст.

109. **Синтетическая форма спрашивается у того, кто её признаёт** (У-189).
    Сверка двух копий сказала «ноль расхождений» о ветви, в которую не
    заходила ни одна из них: поле-источник я собрал по образцу соседнего, а
    признак у платформы другой. Заводя форму, вызовите предикат, который её
    различает, и убедитесь, что ответ тот, ради которого форма заведена.
    Признак: круглый ноль расхождений на формах, которых у человека нет.

107. **Правило, которое что-то прячет, не решает судьбу написанного**
    (У-188). Условие видимости отвечает на «можно ли это менять отсюда», и
    только на него; «что делать с уже написанным» — второй вопрос, и ответ по
    умолчанию «ничего». Слитые в один, они дают потерю текста, которую чтением
    не видно: у заказчика панель уносила ссылку, потому что поле было спрятано
    предусловием. И та же мысль о сборке строки: поле, которого панель сейчас
    не показывает, своими токенами не распоряжается. Признак: рядом стоят
    «поле выключено» и присваивание пустоты в состояние — спросите, кто
    прочтёт эту пустоту дальше.

108. **Найденное новой формой обхода старше самого обхода — это проверяется**
    (У-187). Рабочее дерево на коммите до сессии и тот же стенд там: одна
    команда против целого захода поисков не в том месте. Класть его надо в
    короткий путь — длинный не создаётся вовсе. Признак: в разборе есть
    «дефект давний», и рядом нет команды, которой это снято.

`tests/gates/phase.txt` — **две строки**: подпись текущей фазы и список закрытых. Порог гейтов — максимум по обеим. Почему не одна — У-25.

## Правила текстов (раздел 7 PRD)

- **Сущности плагина — с заглавной** в любом месте фразы: `Field`, `Value`, `Bar`, `Prefix`, `Separator`, `Block`, `TagWheel`, `Binder`, `Transform`, `Smart Rules`. Слова Obsidian и обычного языка — со строчной: line, note, tag, template, hotkey (Р9).
- **Точка в конце видимой строки не ставится** (Р10). Внутри абзаца точки между предложениями остаются.
- Ссылка на команду, хоткей, настройку или значение оформляется как `<code>` (Ст11).
- Длинное объяснение живёт в `tip`, а не в `desc` (Ст12).

Гейты Г10 и Г17–Г19 проверяют это механически, в обе стороны.

**`README.md` и `instructions.md` сторожит пин, а не вычитка.** `tests/regression/docs_terms_tests.ts` держит их в обе стороны: удалённого контрола и старого имени команды в документах быть не может, а **каждая** команда из `NAMES` обязана быть названа нынешним именем. Убрали контрол или переименовали команду — правьте документы в том же коммите.

Старые имена разрешены ровно в двух секциях, и там они и есть содержание: `## Glossary` в руководстве и `## Terms` в README. Больше исключений нет, и добавлять их не надо.

**Пин ловит имена, а не утверждения о состоянии** (У-64). «Не реализовано», «настройка не показывается» он не видит, и стареет это тише всего: про плавающую кнопку оба документа писали «not implemented» четверо суток после того, как она заработала. Раздел «ограничения беты» перечитывается вместе с каждой правкой, которая эти ограничения снимает. **И правило, названное номером, стареет вместе с номером** (У-135): пишется «следующее исключение спрашивается», а не «двадцать шестое спрашивается», — второе перестаёт быть правдой в день, когда двадцать шестое сделано.

**И сам пин бывает утверждением о состоянии** (У-71). Запрет «этого в тексте быть не должно» зелен именно тогда, когда вещь появилась, а документ о ней молчит: пин руководства запрещал называть плавающую кнопку и справочник команд ещё четверо суток после того, как оба заработали. Заводя такой запрет, пишите рядом, что должно случиться, чтобы его сняли. Про **снятые** контролы список один на все три документа плагина — `REMOVED` в `docs_terms_tests.ts`, и заметка-руководство сверяется им наравне с `README.md` и `instructions.md`.

## Слой настроек

Строится на **декларативном API Obsidian 1.13** (Р2): платформа берёт рендеринг, привязки, валидацию и глобальный поиск. Наше: схема как источник истины, хранилище через шов `getControlValue` / `setControlValue`, свои блоки через `render`, полоса вкладок своей вёрсткой (П-16).

Пятнадцать вещей, на которых легко обжечься — разбор в `docs/LESSONS.md`, раздел E:

1. **Формы определений берутся из типов пакета `obsidian`, а не из документации** (У-19). Проверять по `node_modules/obsidian/obsidian.d.ts`. Там же лежат `aliases`, `type: 'list'`, `type: 'folder'` / `type: 'file'`.

   **Но типов мало: часть правил живёт только в поведении платформы** (У-44). Два, стоившие пяти и трёх заходов:
   - **строку без `name`, `render`, `control` и `action` платформа не рисует вовсе** — отбор идёт до отрисовки (`Z2` в `app.js`), и в типах об этом нет ни слова. Пин на само правило стоит в `settings_layer_tests.ts`;
   - **описание платформа клонирует** (`sg(e) = e.cloneNode(!0)`), поэтому **внутри `desc` не бывает обработчиков** (У-46): они не переносятся. Всё, что отвечает на нажатие, живёт там, где узел принадлежит нам.
2. **`getSettingDefinitions` вызывается часто** — никакого I/O внутри. После записи значения определения надо пересобрать (`update()`) (У-24).
3. **Перерисовка своего блока обязана вернуть скролл и фокус** (У-20). Помощник — `custom/keepview.ts`.
4. **Одна подсказка на узел** (У-21). В своих блоках подпись собирает `custom/dom.ts` → `btn`.
5. **Свои блоки просыпаются от хранилища, а не от шва панели** (У-22). `ConfigStoreAdapter.subscribe` отдаёт изменившиеся **пути**, `SettingsPane.wakeFor` рисует каждого подписчика один раз. Второго входа в пробуждение быть не должно.
6. **До строки заголовка группы ведёт один слот — `extraButtons`** (У-62). Через него приезжают и «?», и сброс, и вводный коллаут, и знак сворачивания; лишние узлы кнопок прячутся классом, а не изобретаются заново. Две ловушки: опора на **порядок** в этом списке ломается от каждого нового слота — искать кнопку по её пометке (У-5), — и, главное, **функции зовутся только у группы, созданной заново** (У-69). При совпадении ключа (`тип + ":" + заголовок`) платформа группу переиспользует и `extraButtons` не трогает: пересборкой определений то, что приехало оттуда, не обновить. Нужно обновлять — запоминайте узел, когда платформа его отдала, и рисуйте сами.
7. **`order` переставляет соседей внутри одного флекса и бессилен между разными** (У-63). Кнопка платформы лежит в `.setting-item-control`, имя — в `.setting-item-name`: чтобы встать до имени, узел должен быть своим и лежать в самой строке заголовка. Переносить чужой узел нельзя — `setChildrenInPlace` это отменит (У-45).
8. **Класс, по которому правило кого-то ищет, обязан существовать в панели** (У-65). Прототип и панель — разные деревья: `.io-usertags` живёт в прототипе, а панель ставит `io-usertagsblock` и `io-vals--tags`. Целый блок правил по прототипным именам прожил две сессии и не красил ничего. Пин в `settings_layer_tests.ts` сверяет **наборы имён**: поиск подстрокой тут молчит, потому что мёртвое имя — начало живого.
9. **Объявить свойство мало — надо посмотреть, кто выигрывает каскад** (У-67). Узел несёт несколько классов, и соседнее правило по другому его классу с той же специфичностью и ниже по файлу отменяет объявленное молча. За один заход это случилось **дважды**: `.io-callout--group` против `.io-callout`, и в панели TagWheel — «покрасить подсветку» против стоящего ниже «погасить фон тега», а тег и подсветка оказались одним узлом. Признак: `background-color: transparent` рядом с правилом, которое что-то красит, и оба про одну область экрана. Пин в `settings_layer_tests.ts` разбирает каскад — но **только по перечисленным в нём наборам классов**: завели правило, решающее вид, — впишите его набор.
10. **Отрезок оформления режет платформа, и режет по своим границам** (У-68). `Decoration.mark` на длинный отрезок — это столько кусков, сколько раз внутри меняется чужая разметка; фон, скругление и поля на каждом куске разваливаются. Сплошное ставится на **строку**, а цвет отдаётся переменной, которую читают стили.
11. **Одной библиотеки в сборке платформы бывает две копии, и наружу отдана не та, на которой она работает сама** (У-75). В `app.js` Obsidian 1.13.7 лежат два `drawSelection` CodeMirror: копия для плагинов рисует `.cm-cursor` и для пустого отрезка, а копия, на которой собран редактор заметки, главный пустой отрезок не рисует вовсе — курсор там родная каретка браузера, и из CSS у неё берётся только `caret-color`. Отсюда «цвет каретки работает, а толщина только на выделении». Признак: настройка действует ровно в одном состоянии экрана. Искать не своё правило, а **кто рисует то, что видно** — по имени класса в DevTools.
12. **Скриншот показывает итог, но не устройство** (У-70). Замерить по нему можно — границы по строкам пикселей, масштаб из известной высоты элемента, — а вывести разметку нельзя: одна картинка выводится из нескольких разных. Догадка не сошлась дважды — просите `outerHTML` из DevTools, это тридцать секунд заказчика против целого захода. **И мерить надо до первой догадки, а не после второй** (У-123): декодировщик PNG на встроенном `zlib` — шестьдесят строк, а цвет подложки известен из конфига заказчика; карта прямоугольников по строкам пикселей нашла три причины из пяти. Признак: в замечании есть картинка, а в разборе — слово «видимо».
13. **Окно, которое иногда показывает решение, обязано говорить и тогда, когда решения нет** (У-80). Пустое место человек читает как «функции нет». Признак, по которому это ищется: константа текста объявлена, экспортирована и нигде не используется. И разбирается такое замечание не третьей догадкой, а тем, что лежит у заказчика на диске: две верных находки могут не объяснять его случай.
14. **`Mod` в хоткее — имя платформенного модификатора, а не буквы** (У-81): `Meta` на macOS, `Ctrl` везде ещё, и так же считает сам Obsidian. Клавиша при этом записана либо в `key`, либо в `code` (`KeyF` = `F`). Правило одно на сверку конфликтов и на запись — `bindingKey` в `settings_backup.js`.
15. **Всё, что меряет положение курсора, меряет его с какой-то стороны, и по умолчанию — справа** (У-76). Справа от конца строки может стоять чужой виджет: `RectangleMarker.forRange` меряет пустой отрезок как `coordsAtPos(head, assoc || 1)`, и на `line.to` выбирает не последний символ, а виджет `side: 1`. Каретка встала у начала плавающей кнопки, ровно на её отступ от текста. Рисуя каретку сами, просите измерение с той стороны, где **текст**. Признак, что замечание пришло не по адресу: выключенная функция «чинит» то, что она не рисует, а величина сдвига совпадает с числом из другой настройки.

**Список, которого нет в схеме, приходит источником по имени:** `optionsFrom: "<имя>"`. Прототип разрешает имя мокданными, панель — конфигом и vault (`SettingsPane.optionsFor`). **Мокданные прототипа в панель не попадают** (Р8, У-23).

## Каталог видимых текстов (10.13.38)

Каждая видимая строка панели имеет **ключ** — `<id группы>.<id строки>.<слот>`, тот самый, что человек видит в `Advanced → Options IDs`. Английская ветка каталога **выводится из схемы** (`catalogEntries` в `src/ui/settings/texts.ts`), а не пишется рядом с ней: у текста один дом, и разойтись двум копиям не на чем.

- **Ключ строит одна функция, и её зовут оба конца** (У-82). Литеральная строка на месте ключа в `ctx.t(...)` запрещена пином: расхождение видно только тем, что перевод не применился.
- **Файлы лежат в `<папка плагина>/texts/<язык>.js`** и читаются адаптером vault, а не через дерево заметок: `.obsidian/**` Obsidian не индексирует (10.13.26 Ф5).
- **В папке текстов один файл — `default.js`, и его ведёт плагин** (10.13.48, решение заказчика). Файлов языка плагин не кладёт вовсе: язык появляется тем, что человек копирует `default.js` под своим именем. Список языков собирается из папки, английский в нём есть всегда.
- **Файл языка — человек** (10.13.46, У-83). Английского файла плагин не кладёт вовсе: снимок английского, положенный при установке и больше не переписываемый, **замораживает** каждую позднейшую переформулировку — в подстановке он стоит раньше схемы. Файл языка не перезаписывается, пока в нём есть хоть одна правка человека; файл, слово в слово равный тому, что плагин написал **в прошлый раз** (то есть равный прежнему `default.js`), — всё ещё его и держится в строю.
- **Каталог собирается одной функцией — `panelCatalog`** (`texts_panel.ts`). Слагаемых три: схема, тексты своих блоков и тексты окон. Собирают его четыре места, и стоит одному забыть слагаемое, как файл на диске разойдётся с тем, что панель спрашивает (У-32).
- **Порядок файла — порядок панели** (10.13.46): вкладка → её коллаут → группа → строка → окно, которое эта строка открывает. Разделом в конце лежит только то, у чего места в схеме нет.
- **Тексты окон — `texts_dialogs.ts`, ключ `dialog.<действие>.<имя>`.** Владелец текста — кнопка, которая окно открывает. Строки, которые собираются по ходу, пишутся с `{0}`: склейка через `+` перевода не переживает.
- **Тексты своих блоков — `texts_blocks.ts`, ключ `block.<блок>.<имя>`** (10.13.47). Владелец — сам блок, и называется он тем же id, что стоит у записи `kind: "custom"` в схеме. Спрашивается текст помощником `sayIn(владелец, ctx)`. **Слова при переезде в каталог не переписываются**: английское берётся из самой константы сверкой, а объявление снимается — иначе у текста два дома (У-32).
- **Гейт Г25 отвечает на «есть ли строка в файле»**, а не на «спрашивает ли её то место, где она нарисована». На второй отвечает пин на литералы. Что осталось за каталогом — перечислено пофайлово в `tests/gates/texts_coverage.ts`, с числом и причиной: молчаливый список исключений и есть тот способ, каким «проверено автоматически» превращается в «проверено ничего».
- **Файл читается как JSON**, а не выполняется: его правит человек, и он бывает сломан (Я1). Границы объекта ищутся по строкам — первая скобка в файле стоит в его шапке.
- **Незаполненное молча уступает английскому** (Я4). Показать ключ вместо текста — это дефект на экране вместо строки в отчёте; отчёт печатает гейт Г24, и краснеет он на **лишнем** ключе, а не на недостающем.
- **Свои блоки спрашивают текст сами** — `ctx.t(ключ, то-что-в-выгрузке)`: у записи `kind: "custom"` нет ни `name`, ни `desc`, и подстановка по схеме до её текстов не достаёт.
- **Имена команд не переводятся** (Я2): Obsidian берёт их из своего реестра, и справочник разошёлся бы с палитрой.

## Модули: один статический `require` на модуль

**Весь рантайм** подключает свои модули **литеральным** `require` — по одному на модуль, без заглушек, без своего кеша и без асинхронных загрузчиков. Не только `main.js`: с 2026-09-07 так же устроены движки под З3 и прослойка макро-рантайма. Причина в У-89 и У-90; перепись модулей и запрет на `require` по переменной держит `bootstrap_loader_tests.js`, поведение сборки — `bundle_onload_tests.ts`.

- **Путь в переменной esbuild не разрешает.** Модуль в бандл попадает только из литерала. Промахнуться мимо литерала нельзя, поэтому запасных путей у загрузки нет и заводить их не надо.
- **Заглушки на месте модуля быть не должно.** Модуль лежит в бандле; не приехал — плагин обязан упасть громко.
- **Шов через `globalThis` — это порядок загрузки, а не гарантия** (У-140). Файл, читающий `globalThis.__inlineOverhaulSharedUtils` вместо своего `require`, получает модуль только при входе через того, кто шов ставит. `status_date.js` так и жил: проверка поведения зовёт движок напрямую, шва там не было ни дня, и все эти месяцы она проверяла **копию** правила, а человек получал общий модуль. С 2026-09-11 модуль берётся `require`-ом и там.
- **Мост `vault_module_bridge.js` снят 2026-09-07** вместе с `build/release_entry.js` и реестром забандленных модулей: реестр существовал ровно затем, чтобы мост нашёл модуль, не читая vault. Точка входа сборки — `main.js`. **Путей внутри vault в рантайме не осталось ни одного**, и это держит сплошной обход в `release_bundle_tests.js`; запрет `require` по переменной — сплошным обходом всего рантайма в `bootstrap_loader_tests.js`.

## Конфиг: три ступени и три шва

`migrateConfig` в `main.js` — единственный путь записи, `ConfigStore` прогоняет через него **каждый** патч. Ступеней три, и **порядок обязателен** (У-13):

1. `normalizeConfigV1` — приём файла версии ниже второй. Только здесь живут переименования вида `leftToRight` → `cycleOrder`. Для патча из панели не выполняется.
2. `config_migration_v2.migrate` — перенос по карте `ROUTES` плюс досыпка умолчаний из схемы.
3. `normalizeConfigV2` — клампы, перечисления и структура на путях версии 2. Идёт на каждом патче.

- **Переименования старой формы читают исходный файл, а не слитый** (У-14). Помощник — `fromFile(path)` внутри `normalizeConfigV1`.
- **«Движок читает ключ» не значит «функция работает»** (У-15). Смотреть надо, кто спрашивает значение после нормализации.
- **Нет контрола — проверьте историю**: это может быть потеря при переносе, то есть нарушение З2, а не задумка (У-16).
- **Новая настройка, разделяющая слитое, выводится из старого контрола**, а не из умолчания схемы (У-17).
- **Одно правило — одно место.** Два объявления одного правила расходятся молча; совпадение держит пин на литералы (У-32).
- **Снятый ключ уходит из файла человека не маршрутом** (У-178). `ROUTES` читает только переезд с версии 1; файл версии 2 клонируется как есть. Снятие живёт списком `REMOVED_V2_KEYS` и идёт на каждом проходе.
- **Нашли ключ, который читают под старым именем, — прогоните всю карту `ROUTES`** (У-39). Из сорока переименованных листьев такой был один, и это ответ, а не догадка. Отличать чтение конфига от чтения `rules`: второе — шов У-18.
- **Смотреть не только что нормализация делает, но и откуда её зовут** (У-40). `normalizeTransformConfig` стоял только в первой ступени, и для файла версии 2 ветка Transform не нормализовалась вовсе.
- **Догадка считается после явного выбора человека и уступает ему** (У-33).
- **Список условий, при которых код молча возвращается, — часть разбора** (У-41). Тихий отказ неотличим от дефекта: у `moveLine` таких условий четыре, и одно из них стоило заказчику сессии.
- **Форма версии 1 осталась в одном месте, и это шов** (У-18): `serializePkmOrderForMacro`. Меняются источники значений, не имена ключей. Второй, `rules_markdown_builder.js`, ушёл 2026-09-13 вместе со служебным файлом правил (PRD 10.13.52, П-13); третий, `readFieldsWorkshop`, — 2026-09-03 вместе с конфиг-заметкой (PRD 10.12).

Карта чтений собирается, а не вспоминается: `node tools/read_map_v1.js . read_map.md`. Отчёт о миграции конкретного `data.json` — `node tools/migration_report.js <файл>`.

**Расхождение между копиями одного правила меряется до сведения —
`node tools/form_divergence.js`** (У-194, правило 114). Заведён по его слову
2026-09-15 «уборку кода, но без риска дефектов»: сводится только то, у чего
расхождение измерено и равно нулю, остальное называется числом и остаётся
решением заказчика. Контролей у стенда пять, и каждый на свой шаг обхода.

**Долг копий закрыт 2026-09-16 и закреплён списком, а не числом.** Мера —
`node tools/rule_copies.js`, род каждого имени печатает
`node tools/rule_copy_shapes.js`, а список имён с вердиктами держит
`tests/regression/rule_copies_debt_tests.js`: **новое второе объявление роняет
проверку и называет имя**. Сколько имён в долге сегодня, говорит прогон, а не
эта строка (У-145). Заводя второе объявление нарочно, впишите его туда вместе с
причиной — иначе следующая сессия начнёт разбор заново. И род «не правило»
(доставалка модуля, ленивая сборка своего экземпляра) печатается **отдельным
списком**, а не прячется из долга молча (правило 119).

**Обход обеих дорог — `node tools/line_matrix.js`, и вторым заходом он гоняется
с `--split`:** тот разводит разделители из его **нынешнего** файла, а не из
хранимой копии, которая стареет молча (У-147, У-190).

**Совпадающие разделители — основной случай, а не край** (его слово 2026-09-15:
«в основном разделители будут одинаковые (сепаратор1=сепаратор2) у всех
пользователей, нужно, чтобы в этом случае проблем не было и плагин работал
корректно»). Отсюда два следствия. Первое: прогон **без ключа** и есть главная
мера, а `--split` — способ увидеть то, что совпадение прячет, а не целевая
настройка. Второе: «разведите разделители» — не ответ на дефект и в цене
правки таким доводом пользоваться нельзя. Там, где текст человека и правый
Block делит один и тот же знак, правило обязано решать само.

**Замечание вида «панель и команда дают разное» воспроизводится стендом, а не
рассуждением:** `node tools/line_bench.js` гоняет строку через те же определения
команд и те же ключи, что и плагин, на настоящем `data.json` заказчика. Стенд
собирали заново дважды, и оба раза он называл причину за один заход; третий раз
собирать не надо — **и «быстро проверить соседнюю форму сбоку» это тоже
сборка** (У-197). У панели есть сессия: своя проба, которая её открыла и не
закрыла, сравнивает полосу панели с законченной строкой команды и объявляет
расходящимся **всё подряд**. Новая форма дописывается строкой в корпус
`tools/line_matrix.js`. Внутри — контроль «панель открылась» (У-152) и правка отрезком,
а не строкой целиком: вид панели пишется различием, и подделка, которая границы
игнорирует, отвечает мусором.

**Сводную строку этого отчёта читать целиком** (У-72). Его категории и ветки конфига — разные словари: «уступило форме v2» ложится в ту же ветку `_unmigrated`, что и «маршрута нет». 2026-09-05 я прочёл «в `_unmigrated` 0» как «ничего не потеряно» и написал это заказчику, пока у него там лежали 22 листа. Теперь отчёт печатает число из самой ветки отдельной строкой и сам говорит о расхождении.

## Команды: ID и имена

Схема идентификатора — **один модуль**, `src/features/command_ids.js` (У-26).

- ID — kebab-case без префикса плагина (T7); имя — без префикса плагина и модуля (T6), берётся из списка `COMMANDS` в прототипе.
- Идентификатор, уже отвечающий T7, **не переименовывается**: Р3 даёт один разрыв совместимости, а не два.
- Карта старых и новых ID — `docs/command_ids_v1_v2.md`, выводится `node tools/command_ids_doc.js --write`. Руками не правится.
- Идентификатор строки Binder лежит **в конфиге**; старая форма пересобирается из имени строки нормализацией.
- **Дочерний Field подписан двумя способами, и это шов:** ключ Order оканчивается на `_sub`, подпись в имени команды — на `-sub` (У-7).
- Список всех команд для справочника 10.5 — `buildOwnCommandList` в `main.js`. Проверка обязана звать её (У-4).
- Совпадения kebab разводятся против идентификаторов ядра (У-27).
- **Команды PKM строятся из конфига и заводятся один раз** (У-79). `buildPkmCommandDefs` берёт `cfg`, каждый Field даёт свою пару, а `registerCommands()` зовётся в `onload`. После смены конфига набор команд описывает вчерашний день: хоткей на новый Field виден в справочнике команд и не виден на экране `Hotkeys` Obsidian. Восстановление копии зовёт его заново швом `refreshCommands` (10.13.40); у Field, заведённого руками в панели, этого шва пока нет.

## Окружение

- Windows, путь проекта с пробелами и кириллицей. Пути в командах брать в кавычки.
- Node 24 запускает `.ts` напрямую (стирание типов). Не поддерживаются: параметры-свойства в конструкторе (`constructor(public x)`), `enum`, `namespace`.
- **Во всём репозитории один перевод строки — LF**, и в хранилище, и в рабочей копии, на любой машине. Это задано `.gitattributes` (`* text=auto eol=lf`), а он сильнее `core.autocrlf`, поэтому форма файла больше не зависит ни от машины, ни от настроек человека. Таблицы «этот файл LF, тот CRLF» больше нет и заводить её обратно не надо (У-77).

  **Привычка остаётся, и стоит она дёшево:** помощник правки читает файл с `newline=""`, убеждается, что возврата каретки в нём нет, и проверяет это же после записи. Теперь это не выбор формы, а сторож: одиночный CR в LF-файле ломает следующую правку по якорю ровно так же, как ломал одиночный LF в CRLF-файле, — и ломает молча. Признак прежний: якорь, которого «нет», хотя он виден глазами.

  **`sed -i` сюда же:** он переписывает файл целиком, и заметно это только сплошной сверкой. Правку в одно слово делать помощником, а не `sed -i`.

- **Heredoc в bash съедает обратные слэши и апострофы** — даже закавыченный (У-12). Сложные строки писать файлом. **И сам файл патча заводить неheredoc'ом, а записью файла**: 2026-09-06 закавыченный `cat <<'EOF'` дважды за сессию снял по уровню экранирования — `\n` в питоновской строке приехал настоящим переводом строки и порвал `.ts`, а `\r\n` вписал настоящий возврат каретки в `CLAUDE.md`, то есть ровно то, что этот же файл запрещает. Признак: питон падает на утверждении о форме файла **после** записи — значит, испортил файл он же. Литеральные `—`, `→`, `⠿` и типографские кавычки в прототипе искать через `chr()`.
  **Обратная кавычка в двойных кавычках оболочки — подстановка команды**, и это правило шире, чем `python -c`: `node -e "…"`, `sh -c "…"`, аргумент `-m` — везде одно и то же. 2026-09-06 оно сработало третий раз за сессию, уже на `node -e`, и вычистило из листа приёмки пять кусков текста в обратных кавычках — имена файлов, номер версии, название кнопки. **Правило простое: текст с обратными кавычками пишется инструментом правки файла, а не через оболочку вообще.** Признак: в выводе `command not found` на слове из вашего же текста.

  **Обратная кавычка в `python -c '...'` — тот же случай**, и текст в кавычках молча исчезает: `` `→` `` превращается в пустоту, а `` `heading jumps` `` — в попытку запустить `heading`. Стоило двух починок 2026-09-04. Правило одно и то же: правку с непростыми строками писать **файлом** в scratchpad и запускать `python <файл>`, а не `python -c`. В самом файле обратный слэш и кавычку собирать через `chr(92)` и `chr(96)`. Первая версия такой правки в `line_pipeline.js` дала `B\s` вместо `"\\s"` — из-за порядка подстановок собственных заглушек, и это тот же класс.
- **`git checkout -- <файл>` здесь уносит работу** (У-10). Откат при проверке мутацией — **копией файла** в сторону и обратно.

  **Постоянное разрешение на уборку с нулевым расхождением — его слово

  на экране». Ответ — да, **когда расхождение измерено и равно нулю**. То есть
  правка файла под З3 **не спрашивается**, если до неё прогоном показано, что
  предмет отвечает одинаково на всех входах и правка не меняет поведения ни на
  одном. Порядок прежний и сокращению не подлежит: полный разбор → измерение →
  правка → мутация; место всё равно получает номер в таблице выше, абзац в
  PRD 3.3 и строку отчёта с тем, чем откатывается.

  **Чего разрешение не покрывает.** Всё, что можно объяснить словами «вы
  увидите вот это»: новое поведение, новый текст, новый контрол, расширение
  признака, снятие ограничения. И «расхождение измерить не удалось» читается как
  «не ноль», то есть спрашивается. Признак, что разрешение применяют не по
  адресу: в отчёте о правке нет числа пар и нет команды, которой это число
  снято.

  сделанное» с указанием, чем откатывается. **Правила это не отменяет:**
  разрешение спрашивается до правки, когда заказчика есть о чём спросить.
- Значения, которые пишутся в конфиг: переименовываются только подписи (З1).
- **Видимое имя плагина — `inlineOverhaul`, идентификатор — `inline-overhaul`** (10.13.42). Имя объявлено один раз, в `manifest.json`: Obsidian сам ставит его перед именем каждой команды. Идентификатор не трогать: он в ключах `hotkeys.json`, в пути папки плагина и в ссылке BRAT.
- **Путь папки копий не восстанавливается** (10.13.44). Это адрес в этом vault, а не настройка: копия читается из той папки, на которую плагин смотрит сейчас. Список таких листьев — `DEVICE_LOCAL_LEAVES` в `settings_backup.js`, и применяется он одной функцией на все три пути: восстановление целиком, по галочкам и сброс.
- **Галочки состава копии — вкладки, а не ветки конфига** (10.13.41). Список `PARTS` в `settings_backup.js` сверяется со схемой пином: новая ветка конфига без галочки молча ездила бы в копии всегда (У-32).
- Хоткеи по умолчанию не ставятся ни одной команде (З7).
- Контрол, который не работает в текущем релизе, в панели не показывается (З8). Обратное тоже верно и стоило трёх находок подряд: **ключ, который движок нормализует и никто не читает, — это не «нет функции», а функция без контрола.** Проверьте историю прежде, чем писать заново (У-16).

## Отказы: что говорится вслух, а что молчит

**Тихий отказ неотличим от дефекта** (У-41). Решение принято 2026-09-08 (Д-4
разбора готовности, PRD 15.2); у отказа три вида, и у каждого своё место.

1. **Человеку сказать — `Notice`.** Он сам позвал, и у него не вышло: команда
   ничего не сделала, файл не записался, копия не восстановилась. Признак —
   отказ на пути, который человек начал нарочно.
2. **В журнал разработчика — `devLog` или `console.error` с приставкой
   `[inline-overhaul]`.** Сломалось невидимое: слушатель, перерисовка, шов.
   Человек придёт со словами «перестало работать», и журнал — единственный
   способ узнать, почему.
3. **Молча — и рядом написано, почему.** Три семьи, и никаких других:
   - **проба** — спросили платформу о том, чего у неё может не быть
     (`app.hotkeyManager`, `dataTransfer`, `getComputedStyle`). Ответ «нет» —
     это ответ, а не отказ;
   - **уборка** — снимаем то, чего может уже не быть (выгрузка, снятый узел,
     закрытая сессия). Цель достигнута в любом случае;
   - **украшение** — рисование, которое не имеет права уронить текст человека
     (предпросмотр, оверлей, полосы). Заметка дороже картинки.

**Пустой `catch` обязан нести объяснение на своём месте** — комментарием внутри
блока или в остатке той же строки. Не абзацем выше: тот объясняет функцию, а
не молчание.

**Проверяется наличие объяснения, а не его слова.** Требовать определённое
слово значило бы объявить негодным всё, написанное своими словами: первая
версия проверки так и сделала и назвала молчанием шестнадцать честных
объяснений. Сторож — `tests/regression/silent_failures_tests.ts`, и **числа
живут в нём, а не здесь** (У-135): при каждом прогоне он печатает, сколько
пустых `catch` в рантайме, сколько объяснено и сколько осталось в долге Д-4.
Долг закреплён **по файлам** и умеет только убывать: новое молчание роняет
проверку в том файле, где его завели, а разобранное обязано уйти из списка тем
же коммитом. Прежние числа стояли здесь строкой и разошлись с прогоном за двое
суток.

**Долг закрыт 2026-09-10: список `DEBT` в стороже пуст.** Значит теперь роняет
проверку **любое** безымянное молчание, где бы его ни завели, — и завести его
«в счёт долга» больше нельзя. Заодно обход ищет по маске, где комментарии и
строковые литералы стёрты: своё же объяснение иначе считается местом (У-138).

в PRD**, к строкам с теми же номерами: здесь остаётся только то, что нужно знать
до первого действия. Раздел сокращён 2026-09-08 — он читается каждую сессию, а
рассказывал о состоянии, которого больше нет (У-31).

- **Список пропусков в `tests/run_all.js` пуст, и пустым обязан остаться.**
  Тихо пропущенный тест — это тест, которого нет (A15).
- **Невключённую проверку ловит линтер, а не прогон** (У-36, A16). Зелёный
  прогон о ней не скажет: она в нём не участвует.
- **Хранилище одно — `src/core/config_store.js`.** Встроенных копий в точке
  входа больше нет, как и заглушек на месте модулей (A33).
- **`no-undef` — ошибка, а не предупреждение.** Следующее имя вне области
  видимости уронит проверку (A42).
- **Предупреждение `no-unused-vars` — указатель на мёртвое.** Снимая мёртвое
  объявление, гоняйте линтер **после каждого снятия**: у него всплывает
  следующее, которое жило только для снятого. Так за один заход снялись 735
  строк старой панели Transform и шесть её помощников по одному.

## Общение

**В документах, которые читает заказчик, предложения не разрываются переносом строки** (его слово 2026-09-11: «предложения должны быть все без разрывов»). Это про `test-vault/Приёмка.md` и всё, что он открывает глазами; в коде и в моих рабочих документах перенос по ширине остаётся.

Документ и комментарии в коде — по-русски, все строки интерфейса — по-английски. Заказчик просит заканчивать ответ **одним конкретным следующим шагом**, а не списком вариантов.

**Любой вопрос к заказчику задаётся интерактивным интервью, а не текстом в ответе.** У каждого вопроса — готовые варианты: сначала рекомендуемый и помеченный как рекомендуемый, затем разумные альтернативы. Варианты — это разбор, сделанный до вопроса, а не переложенная на него работа. Разбор остаётся в тексте ответа; в интервью уходит только выбор.

**Вопрос формулируется тем, что человек видит, а не внутренним шифром** (У-29). Не «В-9», а «всплывающее сообщение при первом запуске после обновления»; не «Р13», а «правило описывать новую функцию в PRD до кода». Номер — после описания, в скобках. **Каждый вариант называет последствие**, а не только действие: что изменится на экране, сколько стоит, чем рискуем.

Это не отменяет правила про один следующий шаг: интервью задаёт открытые вопросы, следующий шаг — то, что будет сделано после ответа на них.
