## 1н. Назначено его ответом В-141 — очередь следующей сессии

**Его слово 2026-09-17, ночь:** «она должна считаться текстом. в зависимости
от настроек плагина может быть разные результаты строки `- [[333/имя]] ::
#processed`, `- [[333/имя]] текст :: #processed` и т.д. — при любом из
вариантов имя преобразованной заметки и текст не должны подмешиваться в left
block».

**Это шире, чем вариант, который был предложен.** Вопрос звучал как «считать
текстом, когда другого текста на строке нет»; он ответил **без условия**: имя
новой заметки не бывает значением Block никогда, есть рядом его текст или нет.

**Где живёт поведение.** Признак «этот токен — наше значение» объявлен один раз —
`makeFieldValueTokenTest` в `src/core/pkm_line_finalize_unified.js`, — и про
ссылку он спрашивает только форму: `isWikilinkToken`. То есть **любая** ссылка
считается значением поля. На этом же стоит деление строки на зоны:
`splitSegments` в `src/core/line_pipeline.js` относит кусок до первого
разделителя к левой зоне, если в нём есть «наши» токены.

**Чем ссылку-значение отличить от ссылки-текста — измерено, а не выведено.** У
его полей типа link список значений **перечислен**: у `Project` это `test1`,
`test2`, `test444`. Ссылка `[[333/123123123123]]`, которую пишет Transform, ни в
одном списке не стоит. То есть признак есть: ссылка — значение поля, если её
цель названа значением какого-то поля; иначе это слово человека.

**Чего этот признак не знает, и это надо спросить у продукта до правки:** поле
типа link с поведением `Free` списка значений может не иметь вовсе. Тогда
признак объявит текстом всё, что человек написал сам. Смотреть надо, как такое
поле объявлено в правилах (`source: "wikilinks:<id>"`, `values`) и что о нём
говорит панель — она же как-то решает, предлагать ли значение.

**Цена и порядок.** Правка в `line_pipeline.js` и
`pkm_line_finalize_unified.js` — оба под З3, и поведение меняется, то есть
постоянное разрешение В-120 сюда **не** распространяется: нужно его слово.
Порядок прежний: полный разбор всех мест → измерение обходом строки двумя
заходами → вопрос → правка → мутация в каждое место.

**Чем закреплять.** Формы для обхода строки уже названы им самим: `- [[имя]] ::
#processed` и `- [[имя]] текст :: #processed`. Обе дописываются в
`tools/line_matrix.js` тем же заходом (У-185), и к ним отрицательный контроль —
строка, где ссылка **и правда** значение поля (`- [[test1]] :: текст`): её
поведение меняться не должно.
